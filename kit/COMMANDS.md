# qa-tester — все команды

Плагин QA-тестировщика для Claude Code. Автор: Nikita Morozov (ניקיטה מורוזוב / Никита Морозов).
Каждая команда делает только своё. Всё, что пишет на доску mifrat, — только после твоего «да».

## Начало работы — меню

Открой новый чат в папке проекта и напиши что угодно («привет», «начинаем») — появится **меню с кнопками**: продолжить с прошлого места / тикеты / регресс / другое (просьбы клиента, полная проверка, негатив, UX, Android, iPhone, следующие 150 в регресс). Можно и сразу писать команду.

**Прогресс сохраняется сам и молча** после каждого тикета/шага (один файл, перезаписывается — без мусора и без сообщений). В новом чате меню предложит «продолжить».

## Подготовка проекта

| Команда | За что отвечает |
|---|---|
| `/qa-onboard` | **Новый проект.** Спрашивает ссылки (сайт, доска mifrat, документация, Figma) и аккаунты; **языки проекта определяет сам** по сайту и документации. Создаёт `.qa/`, базу знаний из документации, ставит браузеры и официальных агентов Playwright, готовит вход под аккаунтами. Один раз на проект. |

## Ежедневная работа

| Команда | За что отвечает |
|---|---|
| `/qa` | **Тикеты из «בבדיקות».** Разбор тикета, проверка строго по требованиям, вердикт. Действие на доске (עבר QA / реджект / статус) — после «да». Телефоны — только если тикет требует, тоже после «да». |
| `/qa #hash` | Проверка **одного тикета**. |
| `/qa-android [раздел или #hash]` | Проверка **только на Android** (Chrome, Pixel 7) — раздел сайта или конкретный тикет. |
| `/qa-iphone [раздел или #hash]` | Проверка **только на iPhone** (Safari, iPhone 13 Mini) — раздел сайта или конкретный тикет. |

## Просьбы клиента

| Команда | За что отвечает |
|---|---|
| `/qa-client [текст/скриншоты]` | **Просьбы клиента → тикеты.** Вставляешь просьбы клиента как есть — агент готовит тикеты «בקשת לקוח: …» на иврите, сравнивает с документацией (меняет / в рамках — **только у себя, документацию не трогает**), после «да» создаёт в «לביצוע» и запоминает в реестре. Дальше при проверке решение клиента главнее документации. |

## Поиск багов без тикетов

| Команда | За что отвечает |
|---|---|
| `/qa-full [раздел]` | **Полная проверка сайта** (новый проект, найти максимум багов): сценарии, негатив, UX, десктоп + iPhone + Android. Сначала план, старт после «да». |
| `/qa-negative [раздел] [устройство]` | **Только негативные и граничные тесты**: неверный ввод, границы, повторы, «назад»/обновление, доступ без входа. |
| `/qa-ux [раздел]` | **Только UX на десктопе**: состояния, сообщения, единообразие, тексты, RTL, ошибки консоли. |

Результат проверок без тикетов — отчёт в `.qa/audits/`. На доску заводится только то, что скажешь.

## Автотесты

| Команда | За что отвечает |
|---|---|
| `/qa-backfill [следующие 150]` | **Записать в регресс уже принятые тикеты** из «הושלם»: первый запуск — последние 150, затем `/qa-backfill следующие 150` и т.д. Отдельно от онбординга — когда удобно. План → «да» → запись по фичам, без запуска. Что не автоматизируется — с причиной; «сданное сейчас не работает» — в отчёт. |
| `/qa-regress` | **Регресс:** прогон записанных автотестов по принятым тикетам («הושלם») — проверить, что ничего не сломалось. Только по команде. |

После «עבר QA» автотест только записывается и не запускается — до `/qa-regress`.

## Сессия и улучшение плагина

| Команда | За что отвечает |
|---|---|
| `/qa-handoff` или «сделай хендофф» | Сохранить сессию вручную (обычно не нужно — сохраняется само). |
| «продолжаем» | **Продолжить** в новом чате с того же места (или кнопка «Продолжить» в меню). |
| `/qa-improve` | **Улучшить плагин** по накопленным урокам: показывает правки → вносит после «да» → обновляет плагин и архивы во всех проектах. |

## Работает само, без команды

- **Уроки:** поправил агента в чате («не так», «запомни…») — он записывает урок (`.qa/lessons.md` проекта или общий `~/.qa-tester/lessons.md`) и применяет дальше.⁠​‌​‌​​​‌​‌​​​​​‌​‌​‌​‌​​​​‌​‌‌​‌​‌​​‌‌‌​​‌​​‌‌​‌​​‌​‌‌​‌​​‌‌​​‌​​​‌‌​​​​​​‌‌​​‌​​​‌‌​‌‌​​​‌​‌‌​‌​​‌‌​​‌‌​​‌‌​‌​​​​‌‌​‌​​​​‌‌​​​​​​‌‌‌​​​​​‌‌​‌‌​​‌​​​‌​​​‌​​​​‌‌​​‌‌​‌​​​​‌‌​‌​‌​‌​​​​‌​​​‌‌​​​​​‌‌‌‌‌​​​‌​​‌‌‌​​‌‌​‌​​‌​‌‌​‌​‌‌​‌‌​‌​​‌​‌‌‌​‌​​​‌‌​​​​‌​​‌​​​​​​‌​​‌‌​‌​‌‌​‌‌‌‌​‌‌‌​​‌​​‌‌​‌‌‌‌​‌‌‌‌​‌​​‌‌​‌‌‌‌​‌‌‌​‌‌​⁣
- **Автотесты** после «עבר QA» записываются (не запускаются).
- **Ежедневная сводка «בדיקה יומית»** в mifrat — в конце сессии `/qa`.

## Команды в терминале (в папке проекта)

| Команда | Зачем |
|---|---|
| `cd .qa/e2e && npm run qa-login` | Вход под тестовыми аккаунтами по паролю (пароли — в `.qa/accounts.env`). |
| `cd .qa/e2e && npm run qa-login:manual -- <аккаунт>` | Ручной вход (SMS, Google, 2FA): откроется окно — войдёшь сам, Enter. |
| `cd .qa/e2e && npm test` | Все автотесты вручную (обычно не нужно — есть `/qa-regress`). |

## Устройства в автотестах

Пометка в названии теста: `@desktop` — только десктоп (Chrome 1440×900), `@mobile` — оба телефона, `@iphone` — только iPhone, `@android` — только Android, без пометки — все три.

## Новый проект — по шагам

1. Создай папку проекта и открой в ней новую сессию Claude (вкладка Code).
2. `/qa-onboard` — со ссылками на доску mifrat и сайт.
3. В окне браузера плагина один раз войди в mifrat и напиши «зашел».
4. Если нужны аккаунты сайта — `qa-login` или `qa-login:manual`.
5. `/qa` — начинаем.
