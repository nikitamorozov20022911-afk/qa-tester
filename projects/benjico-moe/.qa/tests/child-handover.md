## #8ca267 — режим ребёнка привязан к сессии на сервере (2026-11-08, ✅, провёл пользователь)
Источник: бриф `.qa/research/8ca267.md` (раунд 2), итог в `.qa/session.json` (tickets[0]), скрины `.qa/screenshots/8ca267-r2-*`. Десктоп 1440 и 1280.
«מה רצוי»: «אי אפשר לצאת ממצב ילד בלי קוד הורים / סיסמה — גם לא דרך שינוי נתונים בדפדפן. הבדיקה של מצב הילד צריכה להיות בצד השרת». Комментарий программиста 08.11 09:53: режим ребёнка хранится на сервере по session_id входа; без ключа и без `x-child-session` сервер всё равно считает запрос режимом ребёнка; выход — только паролем или кодом родителей (проверенным в последнюю минуту).
Роли: `parent-3` (тот же родитель, PIN нет; ребёнок **QA-R2-V** `26592b73-eaa6-439f-ab3f-d98a0bd1871b`) → гейт «אימות זהות» с паролем; `parent-b` (QA-B1, PIN задан) → клавиатура B3.
**Важно:** после входа в режим ребёнка сессия (файл `.qa/auth/<slot>.json`) остаётся в режиме ребёнка навсегда — выйти можно только паролем/PIN. Старый приём «удалить `benjico\child-context`» больше не выводит из режима ребёнка (только для режима, открытого до 08.11) и в автотестах как выход не используется. Решение 08.11: один слот входа на одного ребёнка, постоянно в режиме ребёнка (`parent-auto` — QA-R2-V, `parent-r21-auto` — QA-R2-1); слота семьи с PIN (`parent-b-auto`, QA-B1) нет — кейсы с PIN-гейтом в автотестах пропущены.
Общий шаг «режим ребёнка, ключ удалён»: передача → «<имя>, בואו נתחיל!» → дом ребёнка → удалить из localStorage `benjico\child-context`.
