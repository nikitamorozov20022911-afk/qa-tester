## FL-01 — Onboarding הד-האנטר

- **Источник:** §13 (תכונה), §16 (מסך), §15, §04, §10, §03. Собран из нескольких пунктов.
- **Роль:** הד-האנטר.
- **Триггер:** §10 AC02 «מאפשר מעבר להרשמה כהד-האנטר» (с עמוד בית להד-האנטרים). §13: «החלק כבר פותח».
- **Шаги** (порядок по описанию §13: «פרטים אישיים ועסקיים, פרופיל מקצועי, מסמכים וחתימה»):
  1. «אוסף פרטים אישיים ועסקיים מההד-האנטר» (§13 AC01) — поля: First name, Last name, Company name, Company number, Username, Phone number, Extra phone number, Email, Address, Website (§16 AC01).
  2. «אוסף פרופיל מקצועי כולל תחומי התמחות, שפות ולינקים חברתיים» (§13 AC02) — поля: Profile picture, About profile, Areas of expertise, Languages, LinkedIn, Facebook, Instagram, Work experiences (§16 AC02).
  3. «מאפשר העלאת עד 3 מסמכים» (§13 AC03, §16 AC03).
  4. «מחייב חתימה דיגיטלית» (§13 AC04; §16 AC04 «מציג רכיב חתימה דיגיטלית»).
  5. «מחייב אישור תנאים באמצעות Checkboxes» (§13 AC05; §16 AC05).
  6. «מעביר את המשתמש לסטטוס Pending עם סיום ההרשמה» (§13 AC06); «מציג הודעת המתנה לאישור Admin בסיום» (§16 AC06).
  7. Дальше — FL-04 (אישור Admin).
- **Успех:** «מאפשר גישה למערכת רק לאחר אישור Admin» (§13 AC07) — после Approved (§15 AC05).
- **Сбои/блокировки:**
  - Без подписи/без чекбоксов — регистрация не завершается (§13 AC04–05 «מחייב»). Текст ошибки в источнике не описан.
  - Больше 3 документов — ограничение «עד 3» (§13 AC03); поведение при превышении не описано.
  - До одобрения доступа нет: «מונע גישה למערכת ממשתמשים שאינם מאושרים» (§03 AC05, §07 AC08).
  - Отказ Admin → Rejected (§15 AC05) + уведомление (§15 AC06). Что видит отклонённый пользователь — не описано.
  - Зависимость: «חסום על-ידי: 15 אישור משתמשים על ידי Admin».
- **Экраны по шагам:** 1–6 — §16 «מסך Onboarding הד-האנטר»; вход — §10 «עמוד בית להד-האנטרים»; после одобрения статус виден в §25 «מסך הפרופיל האישי» (AC05 «מציג את סטטוס האישור של המשתמש»).
- **Статусы (§04):** по §13 AC06 — «Pending» (в §04 — Pending Admin Approval); затем Approved / Rejected (§15 AC05). Статус Draft (§04 AC01) для незавершённой регистрации в §13 не упомянут.

## FL-02 — Onboarding משתמש HR

- **Роль:** משתמש HR (HR Provider).

- **Шаги** (§14: «דומה לזה של הד-האנטר אך פשוט יותר»; порядок явно не задан, ниже — порядок AC):
  1. «מאפשר בחירת Role של HR Provider בהרשמה» (§14 AC01; §17 AC01 «מציג בחירת Role בהרשמה»).
  2. «אוסף פרטים בסיסיים ופרופיל מקצועי» (§14 AC02) — поля: First name, Last name, Username, Phone, Extra phone (§17 AC02); Profile picture, Description about user, Company name, ID number, Area of expertise, Website, LinkedIn, Facebook, Instagram (§17 AC03).
  3. Документы: «מחייב העלאת תעודת עוסק מורשה או חברה בע״מ» (AC03); «מחייב העלאת רישיון עסק» (AC04); «מאפשר העלאת רישיון ניהול לשכה כאופציונלי» (AC05); §17 AC04 «מציג העלאת מסמכים עם סימון חובה/אופציונלי».
  4. «מחייב אישור 3 Checkboxes וחתימה דיגיטלית» (§14 AC06; §17 AC05).
  5. «מעביר את המשתמש לסטטוס Pending עד אישור Admin» (§14 AC07). Дальше — FL-04.
- **Успех:** Approved после одобрения Admin (§15 AC02, AC05); далее доступен §26 «פרופיל בסיסי למשתמש HR» и подача в מכרזים (§14 user story: «כדי לקבל אישור ולהגיש מועמדים למכרזים»).
- **Сбои/блокировки:**
  - Нет обязательного документа (תעודת עוסק/ח.פ., רישיון עסק) или чекбоксов/подписи — регистрация не завершается («מחייב»). Сообщения об ошибке не описаны.
  - До одобрения — без доступа (§03 AC05).
  - Отказ Admin → Rejected (§15 AC05).
  - После одобрения: «חוסם גישה של משתמש HR לדשבורד המלא של הד-האנטר» (§03 AC04); §26 AC02 «אינו מציג דשבורד מלא כמו של הד-האנטר»; §67 AC03 «מגביל את הגישה למכרזים בלבד».
  - Зависимость: «חסום על-ידי: 15».
- **Экраны:** §17 «מסך Onboarding משתמש HR»; после — §26 «פרופיל בסיסי למשתמש HR» (AC03 показывает статус одобрения).
- **Статусы (§04):** Pending (Pending Admin Approval) → Approved / Rejected.

## FL-03 — Onboarding מועמד (6 шагов)

- **Источник:** §18 (תכונה), §19 (מסך), §20, §21, §27, §28, §29, §69, §15 AC04. Собран из нескольких пунктов; порядок шагов — из описания §18.
- **Роль:** מועמד (דני / איתי / ליהי).
- **Триггер:** §12 AC02 «מאפשר מעבר להרשמה כמועמד».
- **Шаги** (§18: «בשישה שלבים: בחירת סוג פרופיל, מילוי פרטים, ייבוא LinkedIn, העלאת CV, יצירת תקציר AI ותשלום»):
  1. **בחירת סוג פרופיל** — «מציג בשלב הראשון בחירה בין Anonymous Profile ל-Open Profile» (§19 AC01); «מאפשר למועמד לבחור פרופיל אנונימי (דיסקרטי)» / «פרופיל פתוח» (§21 AC01–02); «קובע את ברירת המחדל של רמת החשיפה בהתאם לבחירה» (§21 AC03); «מסביר בכל שלב בחירה את המשמעות של כל אפשרות מבחינת פרטיות» (§36 AC05).
  2. **מילוי פרטים** — First name, Last name, Phone, Email, Area, City, Profile picture, About, Area of expertise, Desired positions, Languages, Salary expectation, Social links (§19 AC02; §18 AC02).
  3. **ייבוא LinkedIn** — «מציג שדה להזנת קישור LinkedIn» (§19 AC03); «מקבל קישור LinkedIn מהמועמד» → «מנסה למשוך מידע מהפרופיל באמצעות API / אינטגרציה» → «ממלא שדות פרופיל רלוונטיים מהמידע שנמשך» (§20 AC01–03).
  4. **העלאת CV** — «מאפשר העלאת CV» (§19 AC04); «מפעיל ניתוח AI של ה-CV ליצירת תקציר ומילוי שדות» (§18 AC05); §27: «קורא את קובץ ה-CV», «מחלץ שם, ניסיון תעסוקתי, תפקידים, שפות, השכלה ותחום התמחות», «מחלץ ציפיות שכר אם מופיעות», «מזהה את רמת הניסיון», «ממלא אוטומטית שדות פרופיל רלוונטיים».
  5. **תקציר AI** — «מציג את תקציר ה-AI שנוצר לאישור המועמד» (§19 AC05); тон по уровню: Junior, Mid-level, Senior, Manager או Executive (§28 AC02). §22 AC04 «שומר תקציר AI ותקציר אנונימי»; создание анонимной версии — §29 (в каком шаге onboarding — в источнике не указано).
  6. **תשלום** — «מציג Popup תשלום לפי המסלול הרלוונטי בסיום» (§18 AC06; §19 AC06; §69 AC01–03). См. FL-24.
- **Успех:** «מאשר את המועמד אוטומטית ללא צורך באישור Admin» (§18 AC07; §15 AC04).
- **Сбои/блокировки:**
  - LinkedIn: §20 «[שאלת אפיון] המקור אינו מציין את ספק/מנגנון ה-API» — поведение при неудаче импорта не описано (AC02 «מנסה»).
  - Отказ/провал оплаты в Popup — не описан (§69 «[שאלת אפיון] המקור אינו מציין ספק סליקה»).
  - Отклонение AI-תקציר кандидатом — не описано (только «לאישור המועמד»).
  - Обязательность шагов (можно ли пропустить LinkedIn/CV) — в источнике не указана.
- **Экраны:** 1–5 — §19 «מסך Onboarding מועמד»; 6 — §69 «Popup תשלום»; вход — §12 «עמוד בית למועמדים».
- **Статусы (§04):** кандидат автоматически Approved (§15 AC04/AC05 по смыслу «מאשר מועמדים אוטומטית»). Промежуточный статус до оплаты — не указан.

## FL-04 — אישור משתמשים על ידי Admin

- **Источник:** §15 (תכונה), §75, §76, §04, §73 AC01, §07. Собран из нескольких пунктов.
- **Роль:** Admin; затрагивает הד-האנטר и משתמש HR.
- **Триггер:** пользователь (הד-האנטר / HR) завершил регистрацию и находится в Pending (FL-01 шаг 6, FL-02 шаг 5).
- **Шаги** (порядок не задан явно; ниже — по AC):
  1. Admin открывает управление пользователями: «מציג רשימת משתמשים עם סינון לפי Role» (§76 AC01); «מאפשר סינון לפי Role: הד-האנטר, מועמד, חברה ומשתמש HR» (§75 AC02).
  2. «מאפשר ל-Admin לבדוק מסמכים שהועלו לפני אישור» (§15 AC03); «מציג פרטי משתמש מלאים, מסמכים, חתימות ותשלומים» (§76 AC02).
  3. Решение: «מאפשר ל-Admin לאשר או לדחות הד-האנטרים» / «משתמשי HR» (§15 AC01–02); «מציג כפתורי אישור, דחייה, הסרה וחסימה» (§76 AC03).
  4. «מעביר משתמש מאושר לסטטוס Approved ומשתמש שנדחה ל-Rejected» (§15 AC05).
  5. «שולח התראה למשתמש על אישור או דחייה» (§15 AC06; §73 AC01).
- **Успех:** пользователь получает доступ (§13 AC07).
- **Сбои/блокировки:** Rejected — доступа нет (§03 AC05). Возможность повторной подачи после Rejected — не описана. Причина отказа — не описана.
- **Экраны:** §76 «מסך ניהול משתמשים»; уведомление — §74 «פעמון התראות».
- **Статусы (§04):** Pending Admin Approval → Approved / Rejected.
- **Примечание:** кандидаты в этот поток не входят — «מאשר מועמדים אוטומטית ללא אישור Admin» (§15 AC04).

## FL-13 — זרימת מועמדות אנונימית מקצה לקצה

- **Источник:** §41, §39, §42, §43, §36, §29, §07. Собран из нескольких пунктов; каркас — §41.
- **Роль:** צד שולח (הד-האנטר / מועמד); צד מקבל (חברה / הד-האנטר — בעל המשרה).
- **Триггер:** выбор «פרופיל אנונימי» в FL-11 шаг 3.
- **Шаги:**
  1. **Отправка:** «שולח בשלב הראשון תקציר AI, מידע לא מזהה, שאלות/תשובות ואינדיקציה האם נדרש NDA» (§41 AC01); «שולח תקציר AI של המועמד ללא פרטים מזהים» (§39 AC01); «מאפשר לצרף שאלות מקצועיות» (§39 AC03; §43 AC01).
     - Видно на анонимном шаге: «תקציר AI, תחום התמחות, רמת ניסיון, תפקידים כלליים, ציפיות שכר, אזור כללי, שפות ותשובות לשאלות מקצועיות» (§36 AC03).
     - Не видно: «שם, טלפון, אימייל, לינקדאין, רשתות חברתיות, שמות מקומות עבודה מזהים, מסמכים מלאים או כל פרט מזהה ישיר» (§36 AC04; §39 AC02; §29 AC02–05).
  2. **Проверка получателем:** «מאפשר לצד המקבל לבדוק התאמה ראשונית» (§39 AC04); выбор: «מתאים, לא מתאים, שאלות נוספות, בקשת NDA או בקשת פרופיל מלא» (§41 AC02; §42 AC01–04).
     - שאלות נוספות: «מאפשר לצד המקבל לשלוח שאלות לצד השולח» → «מציג את התשובות שהתקבלו» (§43 AC02–03).
     - בקשת NDA → FL-16.
     - בקשת פרופיל מלא → FL-14.
  3. «מעדכן את סטטוס המועמדות בהתאם לבחירה» (§42 AC05).
  4. **Раскрытие:** «מבצע חשיפה מלאה רק לאחר בקשה, אישור הצד השולח, וחתימת NDA אם נדרש» (§41 AC03).
- **Успех:** полное раскрытие после одобрения (FL-14) или решение «מתאים».
- **Сбои/блокировки:**
  - «לא מתאים» — кандидатура отклонена; уведомление «על דחיית מועמדות» (§73 AC02).
  - Отказ שולח в раскрытии → Full Profile Rejected (§40 AC05).
  - Отказ от NDA → «עוצר את התהליך או מחזיר לאפשרות אנונימית בלבד» (§45 AC06).
  - «מבטיח שמידע אנונימי לא יכיל פרטים מזהים» (§07 AC01); «מונע חשיפת CV מלא ללא הרשאה» (§07 AC02).
- **Экраны:** ожидающие запросы/ответы — §44 «Popup ממתינים»; NDA — §46. Экран просмотра/оценки анонимной кандидатуры получателем — отдельным пунктом не описан (§50 AC03/AC05 частично).
- **Статусы (§06)** (сопоставление по названиям, переходы в источнике явно не заданы): Sent → Viewed → Questions Sent / Waiting for Answer → Waiting for NDA → NDA Signed → Full Profile Requested → Full Profile Approved / Full Profile Rejected → Accepted / Rejected → Closed. Явно названы в AC только Full Profile Approved / Full Profile Rejected (§40 AC05).

- **Шаги:** нажать דיווח → «מאפשר בחירת סיבת דיווח: מידע לא נכון, התנהגות לא מקצועית, בעיית פרטיות, פרופיל מזויף, תוכן לא מתאים, בעיה בתהליך או אחר» (AC02) → «שולח את הדיווח ל-Admin לטיפול» (AC03) → обработка — FL-32.
- **Успех:** жалоба у Admin; уведомление «על דיווח» (§73 AC09).
- **Сбои/блокировки:** текст «אחר» (свободное поле?) — не описан; повторная жалоба — не описана. Список причин управляется Admin (§77 AC04 «Report reasons»).
- **Экраны:** профиль кандидата — отдельным экраном не описан; Popup жалобы — не описан.
- **Статусы:** статусы жалобы — не названы.
- **Примечание:** §83 AC01 упоминает жалобы «על מועמדים, הד-האנטרים, חברות ומשרות», но кнопка описана только «בפרופיל מועמד» (§82 AC01).

## FL-32 — טיפול בדיווחים, משובים ובקשות עזרה על ידי Admin

- **Источник:** §83, §47 AC08–09, §82. Собран из нескольких пунктов.
- **Роль:** Admin.
- **Триггер:** «מקבל דיווחים על מועמדים, הד-האנטרים, חברות ומשרות» (AC01); «מקבל Feedback ממועמדים והודעות 'משהו לא תקין'» (AC02); «מקבל בקשות עזרה בזיהוי או בביטחון» (AC03) — в т.ч. из Representation Work (§47 AC08–09).
- **Шаги:** «מאפשר ל-Admin לטפל בדיווח ולשנות סטטוס» (AC04); «מאפשר ל-Admin להתערב כאשר מועמד אינו מרגיש בטוח להמשיך בתהליך» (AC05); сообщение Admin — уведомление «על הודעת Admin» (§73 AC09).
- **Успех:** жалоба обработана (статус изменён).
- **Сбои/блокировки:** статусы жалобы и форма вмешательства — не описаны.
- **Экраны:** экран Admin для жалоб — отдельным пунктом не описан; «Admin Portal» (§47 AC08) — не описан.
- **Статусы:** не названы.
