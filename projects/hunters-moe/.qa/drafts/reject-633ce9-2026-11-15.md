# #633ce9 — reject draft 2026-11-15

## Title
Code window not shown right after onboarding; «הקוד הסודי שלי» does nothing; reset handles the wrong request; e-mail with the new password is not sent and there is no copy option

## What exists
Works: every user has a code (format XXXX-XXXX-XXXX, also old users); the window «הקוד הסודי שלכם» with the client's text, «העתקה» (copies the exact code) and «שמרתי את הקוד» (closes it, does not come back) in he/en/ru/ar and on 375 px; Admin › user profile shows «קוד סודי» instead of «כרטיסים שמורים» and it matches the user's code; /login has «שכחתם סיסמה? פנו למנהל המערכת» with a form that works without login (e-mail, code, message), validation, the same answer for an unknown e-mail, limit 5 per day; the request reaches «דיווחים ופניות» with the «שחזור סיסמה» label, the counter and «תואם / לא תואם»; the admin's «הגדרת סיסמה חדשה» creates a temporary password.
Not done:
1. New user: the code window does not open right after onboarding. A new head hunter (qa-hunternew-4674404c@fldubai.com) finished onboarding → /onboarding/pending — no window (3 reloads), also not on the home page. After Admin approved the user, still no window on /onboarding/pending and on «/»; it opened only later, on the first visit to /collaborations.
2. The account menu item «הקוד הסודי שלי» does nothing: click → the server answers 200 with the code, but no window opens (4 of 4, demo-company-1 and demo-talent-1, on /collaborations and /profile, no console errors).
3. The admin's reset is tied to the newest open request, not to the request with the matching code. demo-talent-3 had R-30 with the correct code («תואם») and newer R-31/R-32 with a wrong code («לא תואם»). The profile showed only the newest request R-32 («AAAA-BBBB-CCCC לא תואם»), «הגדרת סיסמה חדשה» closed R-32 («טופל»), and R-30 with the correct code stayed «פתוח».
4. The new password is not e-mailed to the user. After «הגדרת סיסמה חדשה» (confirm text says «…ולשלוח אותה לאימייל של המשתמש/ת?») the profile shows «שליחת אימיילים לא מוגדרת. מסרו את הסיסמה למשתמש/ת בדרך אחרת». The admin has no choice between e-mail and copy, and there is no copy button next to the temporary password (it disappears after a reload).

## What is needed
1. A new user (any role) sees the window «הקוד הסודי שלכם» with the code, the text «זה הקוד הסודי שלך לשחזור כניסה…» / «מומלץ לשמור אותו מחוץ למערכת…», «העתקה» and «שמרתי את הקוד» right after the last onboarding step — also when the account then waits for Admin approval (on /onboarding/pending). Until «שמרתי את הקוד» is clicked it keeps opening, as now.
2. «הקוד הסודי שלי» in the account menu opens the same window with the user's code (copy + close), on every page.
3. In Admin › the user's profile the admin sees the password-recovery requests of this user with «תואם / לא תואם» and resets the password for the request whose code matches (e.g. the newest request with «תואם» is shown, or each request has its own button). The request that was handled becomes «טופל»; a request with a wrong code is not used for the reset.
4. The temporary password is generated by the system (as now — fine). After it is generated the admin has two options: «שליחה לאימייל של המשתמש/ת» — the password is e-mailed to the user's address (as the ticket says, item 4), in the user's language, with a link to /login; and «העתקה» — a copy button next to the shown password, so the admin can pass it to the user another way. E-mail sending must work on the site (now: «שליחת אימיילים לא מוגדרת»).
Done when: a new user sees the window right after onboarding; the menu item opens the window; with one correct and one wrong request the reset uses and closes the correct one; the admin can both e-mail and copy the temporary password, the user receives the e-mail and can log in with it and change it in «שינוי סיסמה».

## Steps
1. Register a new user → finish onboarding → no code window on /onboarding/pending or the home page.
2. Log in as demo-company-1 → account menu → «הקוד הסודי שלי» → nothing opens.
3. /login → «פנו למנהל המערכת» → send a request for demo-talent-3 with the correct code, then one with a wrong code → Admin › משתמשים › demo-talent-3 → the block shows only the newest (wrong) request → «הגדרת סיסמה חדשה» → it closes the wrong request; the correct one stays «פתוח» in «דיווחים ופניות».
4. After «הגדרת סיסמה חדשה»: «שליחת אימיילים לא מוגדרת…», no e-mail.
