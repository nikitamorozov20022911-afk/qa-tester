# AL-01: Обычный пользователь читает AuditLog напрямую через API — 200 и пустой список
- Фича/экран: API Supabase REST `/rest/v1/AuditLog` (RLS)
- Тикеты: #fc4fa4 (dc0451ee552ed1b25afc4fa4)
- Роль/аккаунт: user «בדיקה» (wojeg27104@blobapps.com), .qa/auth/user.json
- Устройство: desktop 1440×900
- Тип: негатив (доступ, API)
- Предусловия: сессия пользователя; токен — из localStorage страницы (`sb-<ref>-auth-token` → access_token); apikey — из любого запроса страницы к Supabase. Только чтение.
## Шаги
1. Открыть /dashboard под user, взять токен из localStorage.
2. GET `{supabase}/rest/v1/AuditLog?select=*` с заголовками `apikey` и `Authorization: Bearer <токен user>`.
## Ожидаемо
- Статус 200, тело — пустой массив `[]` (0 записей), в т.ч. нет записей своего аккаунта.
- 200 + [] вместо 403 — принято (решение 12.11: AuditLog закрыт RLS, обычное поведение Supabase на SELECT).
