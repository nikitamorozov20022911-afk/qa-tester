## L-20261007-1 · Автотесты: только генерировать, не запускать
- Правило: после «עבר QA» автотесты по тикету писать (план + файлы тестов), но НЕ прогонять — ни @prod-safe, ни @writes. Допустима только проверка компиляции `npx playwright test --list`. Запуск — позже, в регрессе (/qa-regress), по команде пользователя.
- Почему: «автотесты генерируй но не запускай - в будущем будем запускать для регрессий».
- Пример: #550e01db — тесты 2.1–2.3 (@writes) были прогнаны до этого указания; дальше 1.1 и 11 тестов #ca557707 только написаны.
- Источник: сообщение пользователя, 2026-10-07
- Область: проект
- Статус: действует

## L-20261008-1 · Конец сессии: список тикетов вместо «בדיקה יומית» на доске
- Правило: в конце сессии не выделять тикеты на доске и не создавать сводку «בדיקה יומית» — просто написать пользователю названия тикетов по группам: прошли / вернулись (реджект) / новые.
- Почему: «не надо выделять напиши просто название тикетов».
- Пример: Techory, 2026-10-08 — после Multi-select остановлено, выдан список.
- Источник: сообщение пользователя, 2026-10-08
- Область: проект
- Статус: действует

## L-20261014-1 · Реджект — только «דחה משימה», исходный баг не закрывать
- Правило: реджект делать только как «דחה משימה» (task_add_rejection — новый реджект поверх). При реджекте НЕ закрывать (task_resolve_rejection) исходную запись-описание бага (is_initial_bug=true): в баг-тикетах описание живёт в этом реджекте, закрытие убирает главный тикет. Исходный баг закрывается только при «прошёл».
- Почему: «ты делаешь реджект не через кнопку דחה משימה тем самым убираешь главный тикет. делай реджекты только через דחה משימה».
- Пример: #cdf10b1b 14.10 — закрыл f2dfed62 (исходный баг) и открыл новый реджект.
- Источник: сообщение пользователя, 2026-10-14
- Область: проект
- Статус: действует
- Противоречит: общий урок L-20261008-3 «При новом реджекте закрывать исправленные старые» — для is_initial_bug не применять.

## L-20261014-2 · В сводках — только то, что осталось
- Правило: в сводках и строке статуса не перечислять уже сделанное; писать только, что осталось сделать (ждёт пользователя / в работе / не начато).
- Почему: «не пиши то что мы уже сделали. напиши то что осталось сделать».
- Пример: Techory 14.10 — сводки со списками «прошли/сделано».
- Источник: сообщение пользователя, 2026-10-14
- Область: проект
- Статус: действует

## L-20261014-3 · Название тикета на иврите — отдельно от русского текста
- Правило: в сообщениях пользователю название тикета на иврите не смешивать в одной строке с русским текстом и #hash (ломается направление текста). Формат: #hash на своей строке/ячейке, название на иврите — отдельной строкой или в отдельной колонке таблицы, без русских слов и знаков вокруг.
- Почему: «когда пишешь название тикета и в тикете есть иврит то текст путается».
- Источник: сообщение пользователя, 2026-10-14
- Область: общий (кандидат)
- Статус: действует

## L-20261018-1 · Непереведённые тексты на иврите — не баг
- Правило: не заводить баги и не делать реджекты за непереведённые на иврит тексты/форматы дат в интерфейсе (HE-локализация не нужна). Функциональные сбои, которые проявляются только в HE (что-то не работает), — по-прежнему находки.
- Почему: «перевод на иврит не нужен» — пользователь удалил баг #cecff8 (Dispatch/даты/STOP не переведены).
- Пример: Techory 18.10 — баг #cecff8 удалён пользователем.
- Источник: сообщение пользователя, 2026-10-18
- Область: проект
- Статус: действует

## /qa-client: тикеты создавать сразу, без «да»
- Правило: просьбы клиента, которые пишет пользователь, сразу создавать на доске в «לביצוע», без показа таблицы и без ожидания «да». Неясное уточнять вопросом, но не тормозить создание остального.
- Почему: «все тикеты которые я тебе пишу сразу открывай не жди от меня конкретного да», пользователь на созвоне с клиентом.
- Источник: сообщение пользователя, 2026-10-28
- Область: проект
- Статус: действует

## /qa-client: одна просьба клиента = один тикет, даже большая
- Правило: большую фичу клиента не дробить на несколько тикетов — один тикет с разделами в описании.
- Почему: «нет, в 1 тикет делай» — после разбивки GPS Workflow на 4 тикета (2026-10-28).
- Источник: сообщение пользователя, 2026-10-28
- Область: проект
- Статус: действует

## L-20261117-1 · Все сообщения пользователю — только на русском
- Правило: любые сообщения пользователю (включая короткие пояснения между шагами и отчёты агентов, пересказанные пользователю) — только на русском. Английские фразы не вставлять; иврит — только в названиях тикетов и текстах для доски.
- Почему: «пиши мне только на русском» (после пары коротких английских реплик в сессии 17.11).
- Источник: сообщение пользователя, 2026-11-17
- Область: общий (кандидат)
