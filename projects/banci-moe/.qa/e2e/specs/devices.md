# План автотестов: devices

Источник: `.qa/tests/devices/DEV-001.md` (#8b11bf53), `DEV-004.md` (#ec8ab82d, #1c852837), `DEV-005.md`, `DEV-006.md` (#1c852837), `DEV-007.md` (#ec8ab82d) — «עבר QA» 2026-10-12; `DEV-008.md` (#0af24eb7) — «עבר QA» 2026-10-14.
Все тесты — только просмотр (`@prod-safe`): окна открываются и закрываются через «ביטול» / «סגירה». НИКОГДА не нажимать «הסרה», «שמירה», не переключать роли.
Роль устройства сессии `.qa/auth/user.json` (главное / дополнительное) заранее не известна — тесты проверяют «свою» строку («הטלפון הזה») и сравнивают с обычной загрузкой, а не конкретную роль.
Сбой сети (вместо авиарежима / подмены fetch в Web Inspector) — `page.route` на запрос списка устройств: `route.fulfill({ status: 500 })` или `route.abort('internetdisconnected')`; затем `page.unroute`.

Не автоматизируется (вручную, см. кейсы):
- DEV-007 (#ec8ab82d) — «ניהול כל המכשירים עם סיסמה»: ввод пароля аккаунта; плюс нужна сессия именно дополнительного устройства.
- DEV-005 в части «главное устройство Mac» — нужен профиль Chrome `auth/profiles/devA` (не storageState); автотест 2.1 покрывает тот же сценарий для устройства сессии.
- DEV-002 / DEV-003 — нужны два зарегистрированных устройства одновременно.

### 2. «מכשירים» — ошибка загрузки и «נסו שוב»
**Seed:** `tests/seed.user.spec.ts`

#### 2.1 После ошибки загрузки и «נסו שוב» своя строка снова «הטלפון הזה», без баннера «לא מחובר», экран = обычной загрузке #1c852837 @iphone @prod-safe
**Device:** iphone
**Users:** user (в подписке 2/2 устройства; устройство сессии зарегистрировано)
**Steps:**
1. Открыть `/account/devices` без подмены; дождаться списка. ПРЕДУСЛОВИЕ: одна строка содержит «הטלפון הזה» и нет «הטלפון הזה עוד לא מחובר לחשבון» — иначе тест падает с сообщением «сессия user.json не привязана к устройству — обновить qa-login», а не продолжает. Запомнить эталон: тексты всех строк устройств (роль «מכשיר ראשי»/«מכשיר נוסף», «מקבל התרעות», статус «מחובר», «הטלפון הזה»).
2. Включить `page.route` на запрос списка устройств (генератор определяет URL по сетевым запросам в шаге 1) → `fulfill({ status: 500 })`; перезагрузить страницу.
3. Дождаться ошибки и кнопки «נסו שוב».
4. `page.unroute(...)`; нажать «נסו שוב»; дождаться списка.
5. Повторить шаги 2–4 ещё 2 раза; во втором повторе вместо 500 — `route.abort('internetdisconnected')` (замена авиарежима).
6. Нажать свою строку («הטלפון הזה») → окно; закрыть «ביטול» / «סגירה» без изменений.
**Expected:** (источник: «מצב רצוי» реджекта #1c852837; F-01 AC8; комментарий dc96de5)
- При сбое видны «משהו השתבש — לא הצלחנו לטעון את המידע. בדקו את החיבור ונסו שוב.» и «נסו שוב».
- После каждого «נסו שוב»: своя строка содержит «הטלפון הזה» и ту же роль, что в эталоне; тексты всех строк = эталону из шага 1.
- После каждого «נסו שוב» нет текстов «הטלפון הזה עוד לא מחובר לחשבון» и «ניהול כל המכשירים עם סיסמה» (count = 0).
- Окно своей строки содержит «זה הטלפון שבידכם.»; после закрытия URL `/account/devices`, список без изменений.
