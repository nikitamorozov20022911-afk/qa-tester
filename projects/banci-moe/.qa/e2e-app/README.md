# Нативные автотесты Banci (iOS-приложение, реальный iPhone по кабелю)

Appium XCUITest через REST (`fetch` к `http://localhost:4723`), Node 22, **без npm-зависимостей** (ставить ничего не нужно).
Веб-тесты Playwright — отдельно, в `.qa/e2e/`.

## Перед запуском
1. iPhone подключён кабелем, разблокирован, приложение Banci (TestFlight, bundle id `com.julius.banci`) установлено и **уже залогинено** (тесты пароли не вводят и аккаунты не создают; `noReset: true` — данные и вход не сбрасываются).
2. Appium запущен: `appium` (порт 4723), WebDriverAgent собран (см. скилл `qa-device`).
3. Переменные окружения — **личные значения, в репозиторий не записывать**, брать из `~/.qa-tester/devices.md`:

## Запуск (только по `/qa-regress` или просьбе пользователя)
```
cd .qa/e2e-app
npm test                       # все тесты по одному (один телефон)
npm run test:list              # список
npm run test:ticket -- "#1273694f"   # тесты одного тикета
```
Итог — `results/results.json` (у упавших — ошибка и скриншот в `results/`). Статус `skipped` — тест сам пропустился: ручное предусловие (громкость, разрешения ОС) не выставлено, причина в `error`.

## Правила
- Элементы ищутся по видимому тексту/accessibility name на иврите (Expo/RN: `Button` / `StaticText` / `Other` с `name`). Ожидания — опрос результата, без фиксированных пауз.
- Перед каждым тестом приложение перезапускается (`terminateApp` → `activateApp`).
- **Никогда** не нажимать «חיוג ל-101» (настоящий звонок). Системные окна закрываются только кнопкой отмены по её названию (`ביטול` / `Cancel` / `Отменить`).
- WhatsApp: только системное окно «открыть WhatsApp» → отмена; чат не открывается, сообщения не отправляются.
- Мониторинг тесты не запускают (на шаге 3 «התחלת ניטור» не нажимается) — сеансов в истории не создают. Исключение — тесты с пометкой `@data` (#0b59fe, #3c3460, #8d2595, #af53b1, #7b5462, `lib/monitoring.mjs`): запускают мониторинг и завершают его слайдером «כבה את המצלמה» (#af53b1 — закрытием приложения `terminateApp`), создают сеанс в «היסטוריה»; идут только с `BANCI_MONITORING=1` (без неё — пропуск), телефон на зарядке, камера на освещённую сцену. Тестовый сигнал на шаге «בדיקת בטיחות» звучит громко (и в беззвучном).
- «הפרטים עדיין נכונים» в карточке ребёнка тесты не нажимают (сбросит просрочку #5ffe7018 — вернуть может только программист). Фото ребёнка не сохраняется («שימוש בתמונה» не нажимается).
- #3f4c7c1e (`tests/children/photo-no-face-hint.test.mjs`): перед прогоном положить телефон так, чтобы в кадре камеры не было лиц; разрешение камеры уже выдано (`BANCI_CHILD` — ребёнок, по умолчанию «QA בדיקה»).
- Язык телефона тесты не меняют. Для #f7167929 главный прогон — при English (или русском) языке iPhone, выставленном вручную.
- Онбординг (#8ff79b80) не автоматизируется — повторить на существующем аккаунте нельзя (кейс `.qa/tests/onboarding/ONB-001.md`, вручную на новом аккаунте).

- «בדיקת בטיחות» (#e2f5c7, #2bc13b): громкость и разрешения iOS Appium не меняет — выставлять вручную. По умолчанию (громкость на максимуме, всё разрешено) идут 1.8 и 1.10; 1.9 и 1.11 — только с `BANCI_VOLUME` / `BANCI_PERMISSION_OFF`. После — вернуть громкость на максимум и включить разрешения.
- #5a6377 (обрезка текстов) — только визуально, вручную (`.qa/tests/design-system/DS-004.md`).

План: `specs/app.md`.
- Авиарежим (#7b5462, 1.31): в авиарежиме Appium теряет связь с WDA (socket hang up) — тест после «готово» создаёт новую сессию `app.reconnect()` без перезапуска приложения (мониторинг не прерывается). Если Appium не даёт открыть вторую сессию на тот же телефон — запустить `appium --session-override`.

## Android (Pixel по кабелю) — отдельный раннер на adb
Тесты `android/tests/*.test.mjs`, раннер `run-android.mjs`, клиент `android/lib.mjs` (uiautomator dump + `input tap`, без Appium и зависимостей). Приложение `com.eitan.poolsafety` уже залогинено; Мониторинг тесты не запускают.
```
export BANCI_ANDROID_SERIAL=…        # adb devices; серийник — из ~/.qa-tester/devices.md (в репозиторий не писать)
npm run test:android                 # все Android-тесты по одному
npm run test:android:list
npm run test:android:ticket -- "#8edb6e"
```
Итог — `results/results-android.json`. Режим звонка (`cmd audio set-ringer-mode`) и громкость медиа (`cmd audio set-volume 3 N`; `cmd media_session volume --set` не работает) тесты ставят по adb и **возвращают** (не прочитали прежнюю громкость — ставят максимум).

| переменная | что |
|---|---|
| `BANCI_ANDROID_SERIAL` | серийник телефона (обязательно) |
| `BANCI_ANDROID_PACKAGE` | (необязательно) по умолчанию `com.eitan.poolsafety` |
| `BANCI_SOUND` | (необязательно) `1` — разрешить тест 1.48 (#8edb6e) и прохождение шага 1 в Android-тестах шага 2 (#ab4270, 1.52–1.54), если там просят тестовый звук: реальный звук ГРОМКО (звучит и в беззвучном), иначе пропуск. Остальные Android-тесты тихие |
| `BANCI_SCENE` (Android) | как для iOS: `pool-pale` / `no-water-light` / `no-water` — физическая сцена перед камерой Pixel (видео/картинка на экране Mac), иначе пропуск |
