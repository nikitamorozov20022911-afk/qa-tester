# MON-029: Нагрев телефона — MODERATE: баннер «הטלפון מתחמם», мониторинг идёт; SEVERE: сбой «הטלפון התחמם» (Android, ВРУЧНУЮ + веб-мок)
- Фича/экран: monitoring — экран мониторинга, сбой «הטלפון התחמם» (F-21 «זיהוי כשל בניטור» AC5, AC9; S-14 AC1–3, AC7; FL-06)
- Тикеты: #56611b (id 84a6e3d6761175363156611b; commit 0cbf21f, OTA runtime 0.1.1; чтение термостатуса — нативная Android build 9+ / versionCode 10)
- Роль/аккаунт: dadayo (аккаунт, под которым залогинено приложение)
- Устройство: нативное приложение Android (Eitan) на Pixel 6 по кабелю USB (он же зарядка), adb; создаёт сеанс в «היסטוריה» (@data)
- Тип: негатив (нет ложного сбоя) + позитив (настоящий перегрев) + граница (MODERATE / SEVERE)
- Предусловия: сборка с чтением термостатуса (Pixel 6 — versionCode 10), приложение закрыть/открыть ×2 (OTA); батарея Banci «Unrestricted»; телефон на подставке, на зарядке; видео бассейна на экране Mac; разрешение пользователя на `adb shell cmd thermalservice override-status` (симуляция на тестовом телефоне, после — обязательно `reset`)
## Шаги
1. Mac: лог раз в 60 с — `adb shell dumpsys battery | grep temperature` и `adb shell dumpsys thermalservice | grep 'Thermal Status'`.
2. Pixel: «בית» → «התחלת ניטור» → «בדיקת בטיחות» → кадр бассейна → «מי בבריכה היום?» → «התחלת ניטור».
3. Реальный мониторинг на зарядке ≥ 5–15 мин (исходный ложный сбой был на ~3-й мин), телефон не трогать. Скриншоты: старт, 3, 5 мин.
4. `adb shell cmd thermalservice override-status 2` (MODERATE) → ждать ~60 с.
5. `adb shell cmd thermalservice override-status 3` (SEVERE) → ждать до ~60 с.
6. `adb shell cmd thermalservice reset` → `dumpsys thermalservice`: IsStatusOverride false; в окне сбоя «בדיקה חוזרת».
7. Повторить шаги 4–6 второй раз (×2).
8. «כבה את המצלמה» → итог / «היסטוריית אירועים».
## Ожидаемо
- Шаг 3: нет «כשל בניטור: הטלפון התחמם» и нет «הזיהוי נעצר»; статус «תקין», бассейн не уходит в «לא במעקב» («מה רצוי»: כשל רק כשהמערכת באמת לא יכולה להמשיך לנטר). Если Thermal Status < 2 — записать «MODERATE естественно не достигнут».
- Шаг 4 (MODERATE): максимум баннер-предупреждение «הטלפון מתחמם. הניטור ממשיך, אבל כדאי להעביר אותו לצל ולטעון במטען רגיל ולא במטען מהיר.», статус «תקין», мониторинг идёт, сбоя нет («מה רצוי»: בחימום בינוני — לכל היותר אזהרה עם עצה… בלי להפסיק את המעקב; баннер — «לכל היותר», не обязателен).
- Шаг 5 (SEVERE): сбой «הטלפון התחמם» + «הבריכה לא במעקב — השגיחו עליה בעצמכם.» + «הטלפון חם מדי כדי להמשיך.» и советы (צל, כיסוי…), событие в «היסטוריית אירועים» (F-21 AC5, S-14 AC1/AC3).
- Шаг 6: после reset и «בדיקה חוזרת» мониторинг возобновляется, «תקין» (S-14 AC7).
- Веб-мок (Expo web, логика общая с приложением): `?mock=warm` (статус 2, 36.6°C, медленный анализ 260 мс — старое правило «медленная модель = нагрев») → баннер «הטלפון מתחמם…», без «הטלפון התחמם»; `?mock=hot` (статус 3) → сбой «הטלפון התחמם» · «לא במעקב» и событие. Автотесты: `.qa/e2e/tests/monitoring/thermal-warm-banner-no-failure.spec.ts`, `.qa/e2e/tests/monitoring/thermal-hot-overheated-failure.spec.ts` (@android @data). Реальный нагрев и `override-status` — только вручную на телефоне.
