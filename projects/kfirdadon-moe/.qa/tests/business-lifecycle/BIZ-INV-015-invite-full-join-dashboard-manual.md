# BIZ-INV-015 (вручную): полное вступление по приглашению → дашборд מנהל/ת מגייס/ת без «הגדרות»; повторное открытие ссылки — «כבר נעשה שימוש בהזמנה»
- Фича/экран: /invite/<token> → дашборд нового участника; /settings/users (менеджер)
- Тикеты: #6a993d7ada81dff9be145887 (#145887) — AC2, AC4; связано BIZ-INV-011 (#c31690)
- Роль/аккаунт: менеджер testim + новый участник (пароль и вступление — ТОЛЬКО пользователь)
- Устройство: desktop 1440×900
- Тип: позитив
- Предусловия: агент пароли не вводит и аккаунты не создаёт. Адрес — temp-mail пользователя или ссылка через «העתקת קישור».
## Шаги
1. Менеджер: приглашение «מנהל/ת מגייס/ת» (с шиухом) → ссылка.
2. Пользователь в инкогнито: шаги 1–3 как BIZ-INV-013 (свой пароль, телефон по желанию) → шаг 4: обе галочки → «הצטרפות לחשבון».
3. Посмотреть дашборд и боковое меню.
4. Менеджер: обновить /settings/users.
5. Та же ссылка в новом окне без входа.
6. Очистка (по решению пользователя): участник → «⋮» → «הסרה מהעסק».
## Ожидаемо
- п.3: дашборд рекрутёра «צהריים טובים · <שם>» (приветствие по времени суток); в меню «דשבורד», «מועמדים», «סימולציות», без «הגדרות» / «משתמשים והזמנות» (AC2 «מעבר לדשבורד בהתאם להרשאה»).
- п.4: строка участника «פעיל» (AC2 «סטטוס המשתמש פעיל»).
- п.5: «כבר נעשה שימוש בהזמנה», «הקישור הזה כבר שימש להצטרפות לחשבון, ואפשר להשתמש בו פעם אחת בלבד.», «איך מקבלים הזמנה חדשה?», «כניסה לחשבון» (AC2, AC4).
## Почему вручную
Вступление создаёт аккаунт в Supabase Auth; «הסרה מהעסק» его не удаляет — каждый прогон регресса оставлял бы новый аккаунт. Правило автотестов: «не автоматизируем создание аккаунтов». Экран использованной ссылки покрыт автотестом с подменой ответа (BIZ-INV-014).
