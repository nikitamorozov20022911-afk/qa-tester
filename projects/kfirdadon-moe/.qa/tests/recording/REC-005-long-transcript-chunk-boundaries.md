# REC-005: транскрипт длинного звонка — слова на границах частей по 150 с не теряются и не дублируются
- Фича/экран: транскрипт попытки (get_candidate_report → transcript.segments)
- Тикеты: #0e9f9a (30024c6427c460c2480e9f9a)
- Роль/аккаунт: business (testim), только чтение
- Устройство: desktop 1440×900 (проверка по данным API)
- Тип: граница / регресс бага (только чтение)
- Предусловия: как REC-004 (кандидат «QA-0e9f9a-2110», 1250 с, границы частей 150, 300, …, 1200 с).
## Шаги
1. get_candidate_report → transcript.segments.
2. Сравнить соседние сегменты и окрестность каждой границы 150·k с.
## Ожидаемо (источник: описание бага #0e9f9a «מילה בגבול מקטע נעלמת»)
- У каждого сегмента start ≤ end; start не убывает; соседние сегменты не перекрываются по времени (допуск 0,05 с).
- Нет двух подряд одинаковых сегментов; последнее слово сегмента ≠ первому слову следующего того же говорящего; внутри сегмента нет повтора слова подряд (дубль на склейке).
- Нет пауз между сегментами > 15 с (факт: макс. 7,4 с).
- Возле каждой границы 150·k с (k = 1…, пока < длительности) есть хотя бы один сегмент в окне ±20 с.
- Вручную 21.10 (не автоматизируется — нужна сверка со звуком): слова, пересекающие границы 300, 900, 1050 с, присутствуют ровно один раз (выравнивание alignment.json: 989 слов, 3 расхождения орфографии вне границ).
