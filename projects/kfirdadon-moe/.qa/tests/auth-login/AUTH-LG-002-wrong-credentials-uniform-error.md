# AUTH-LG-002: неверные данные — единое сообщение без раскрытия существования аккаунта, почта остаётся в поле
- Фича/экран: вход (F-05 AC2, S-03 состояние ошибки)
- Тикеты: #6a993d794918a5e83bc3231b
- Роль/аккаунт: guest; адрес qa-nonexistent@example.test (несуществующий), заведомо неверный пароль
- Устройство: desktop 1440×900
- Тип: негатив
- Предусловия: не больше 6 неудачных входов с IP за прогон (лимит Supabase 30/5 мин по IP общий)
## Шаги
1. /login → «מייל» = qa-nonexistent@example.test, «סיסמה» = любая неверная → «כניסה».
2. (ручной шаг) Повторить с адресом существующего тестового аккаунта и неверным паролем; сравнить текст и ответ сети.
## Ожидаемо
- Ответ /auth/v1/token — 400 `invalid_credentials` (тот же код и текст для существующего адреса — без различий).
- Плашка «המייל או הסיסמה שגויים» / «בדקו את הפרטים ונסו שוב. אם שכחתם את הסיסמה, אפשר לאפס אותה.»; не указано, какое поле неверно (AC2: «הודעת שגיאה אחידה שאינה חושפת אם המייל קיים»).
- Поле «מייל» сохраняет введённый адрес (AC2: «והמייל שהוזן נשמר בשדה»); пользователь остаётся на /login.
