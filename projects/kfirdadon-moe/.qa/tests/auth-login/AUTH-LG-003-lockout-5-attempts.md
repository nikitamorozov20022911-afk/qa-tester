# AUTH-LG-003: 5 неудачных попыток → вход заблокирован в браузере на 5 минут, блокировка переживает перезагрузку
- Фича/экран: вход (F-05 треб.7; решение пользователя 14.10: лимит Supabase 30/5 мин по IP + блокировка 5 попыток в браузере, блокировка по аккаунту не требуется)
- Тикеты: #6a993d794918a5e83bc3231b
- Роль/аккаунт: guest; qa-nonexistent@example.test
- Устройство: desktop 1440×900
- Тип: негатив / безопасность
- Предусловия: в автотесте ответ входа подменяется (400 invalid_credentials, 429) — реальные попытки не тратятся
## Шаги
1. 4 неудачные попытки входа.
2. 5-я неудачная попытка.
3. Перезагрузить /login.
4. Сдвинуть `lockedUntil` в прошлое (имитация 5 минут), перезагрузить.
5. Отдельно: ответ сервера 429 (лимит Supabase по IP) на первой попытке.
## Ожидаемо
- После 1–4: «המייל או הסיסמה שגויים», кнопка «כניסה» активна.
- После 5-й: плашка «יותר מדי ניסיונות כניסה» / «מטעמי אבטחה הכניסה נחסמה זמנית…»; кнопка неактивна, текст «אפשר לנסות שוב בעוד 4:5x–5:00»; localStorage `login-lock.v1` = {failures: 5, lockedUntil ≈ сейчас + 300 000 мс}; 6-я попытка не отправляется.
- После перезагрузки — то же (блокировка сохранена).
- После истечения — кнопка «כניסה» снова активна, плашки нет.
- 429 → сразу «יותר מדי ניסיונות כניסה», кнопка заблокирована на ~5 минут.
