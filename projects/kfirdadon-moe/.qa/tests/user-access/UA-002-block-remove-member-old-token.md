# UA-002: после блокировки / удаления участника его старый токен не читает данные
- Фича/экран: /settings/users (F-07, S-05) + Supabase REST
- Тикеты: #4cfd0ae49bece5d24e46d903
- Роль/аккаунт: business (исполнитель) + РАСХОДНЫЙ участник бизнеса testim (жертва, вошёл в своём окне)
- Устройство: desktop 1440×900
- Тип: негатив (безопасность)
- Предусловия: расходный участник (не общие business/user). Удаление необратимо — участник после него непригоден, нужен новый. Блокировку — затем «ביטול חסימה».
## Шаги
1. Жертва входит, из запроса к `/rest/v1/` сохраняется её токен; GET candidates — контроль.
2. business на /settings/users → строка жертвы → «חסימה».
3. Старым токеном жертвы: GET candidates / simulations / businesses / invitations.
4. (Другой расходный участник) business → «הסרה» → тот же GET старым токеном.
## Ожидаемо
- После блокировки и после удаления: 200 `[]` по всем таблицам — данные не отдаются (источник: «מה רצוי» «אחרי … חסימה או הסרה, כל גישה לנתונים עם הטוקן הישן נדחית»; F-07 AC блокировка завершает сессию).
- Примечание: отказ — через RLS (200 []), не 401. Находка: блок не завершает сессию на сервере (`/auth/v1/user` 200 до перехода клиента) — не критерий этого кейса.
