# UA-009 (вручную): блокировка → выброс из сессии и отказ во входе → разблокировка → вход → удаление из бизнеса
- Фича/экран: /settings/users (менеджер) → окно участника → /login (F-07, S-05, FL-07)
- Тикеты: #6a993d7ae4562a7e48cea3ed (#cea3ed) — AC3, треб.2; связано #922c63 (тот же прогон — AUTH-LG-013), #f6e816402bc7433839ec2a6f, #4cfd0ae49bece5d24e46d903
- Роль/аккаунт: менеджер QA-бизнеса (business testim или свой QA-бизнес) + НОВЫЙ участник «R» (вступает и вводит пароль ТОЛЬКО пользователь)
- Устройство: desktop 1440×900
- Тип: позитив + негатив
- Предусловия: адрес temp-mail.org от пользователя. Агент пароли не вводит, аккаунты не создаёт. Сохранённые слоты (.qa/auth/user*.json, ceajoin.json, business*.json и др.) НЕ блокировать и НЕ удалять. Удаление необратимо — R после него непригоден.
## Шаги
1. Менеджер: /settings/users → «הזמנת משתמש» → «שם מלא» «QA-R-<ддмм>», «מייל» = адрес temp-mail, «מנהל/ת מגייס/ת», без шиуха → «שליחת הזמנה». Ожидаемо: «ההזמנה נשלחה», строка «ממתין להצטרפות · בתוקף עד …».
2. Пользователь: письмо → ссылка /invite/… в инкогнито → пароль, согласие → «הצטרפות». Ожидаемо: дашборд R; у менеджера строка R «פעיל». Создать от имени R что-нибудь видимое менеджеру (напр. заметку/приглашение кандидата QA-AUTO-…), окно R не закрывать.
3. Менеджер: «פעולות עבור QA-R-…» → «חסימת משתמש». Ожидаемо: окно «לחסום את QA-R-…? הסשן הפעיל של QA-R-… יסתיים מיד, ולא ניתן יהיה להתחבר עד לביטול החסימה. הנתונים שיצר/ה נשמרים.» → подтвердить. Ожидаемо: «השינוי נשמר — המשתמש/ת נחסם/ה. הנתונים שיצר/ה נשמרים.», статус «חסום».
4. Пользователь в окне R: перейти по меню (без F5). Ожидаемо: /login, «הגישה לחשבון חסומה» — «המשתמש שלכם חסום כרגע…» (AC3 «הסשן הפעיל שלו מסתיים»).
5. Пользователь: почта и пароль R → «כניסה». Ожидаемо: отказ, та же плашка (AC3 «אינו יכול להתחבר»).
6. Менеджер: данные из п.2 на месте, автор — R (AC3 «הנתונים שיצר נשמרים»).
7. Менеджер: меню R → «ביטול החסימה». Ожидаемо: окно «לבטל את החסימה של QA-R-…? … יוכל/תוכל להתחבר שוב עם ההרשאה הקיימת.» → подтвердить → «החסימה בוטלה. אפשר להתחבר שוב.», статус «פעיל».
8. Пользователь: вход R. Ожидаемо: дашборд, роль «מנהל/ת מגייס/ת» как была. Окно не закрывать.
9. Менеджер: меню R → «הסרה מהעסק». Ожидаемо: окно «להסיר את QA-R-… מהעסק? הגישה של QA-R-… לנתוני העסק תסתיים מיד. הנתונים שיצר/ה נשמרים ומשויכים אליו/אליה.» → подтвердить → «המשתמש/ת הוסר/ה מהעסק…», строки R нет.
10. Пользователь в окне R: перейти по меню; затем ввести почту и пароль. Ожидаемо: /login, «הגישה לעסק הוסרה» — «המשתמש שלכם הוסר מהעסק…»; слова «חסום» нет; вход отклонён с той же плашкой.
11. Менеджер: данные из п.2 на месте, автор — R (FL-07 «רשומות שיצר נותרות משויכות אליו»).
## Ожидаемо
См. шаги (источник: AC3, треб.2 #cea3ed; тексты — «מה רצוי» #922c63).
