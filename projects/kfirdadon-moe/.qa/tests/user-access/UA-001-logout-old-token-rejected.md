# UA-001: после «התנתקות» старый access token не читает данные
- Фича/экран: доступ и сессии (F-05), шапка «התנתקות», Supabase REST /rest/v1/*
- Тикеты: #4cfd0ae49bece5d24e46d903
- Роль/аккаунт: business — ОТДЕЛЬНЫЙ вход в собственном окне (не общая сессия .qa/auth/business.json)
- Устройство: desktop 1440×900
- Тип: негатив (безопасность)
- Предусловия: «התנתקות» отзывает ВСЕ сессии аккаунта (scope global) → после проверки .qa/auth/business.json мёртв, нужен `npm run qa-login`. Не запускать параллельно с другими тестами business. Не на проде.
## Шаги
1. В отдельном окне войти как business.
2. Из запроса страницы к `/rest/v1/` взять apikey и access token (только в памяти, не выводить).
3. GET `/rest/v1/candidates?select=id&limit=3` с токеном — контроль.
4. Нажать «התנתקות».
5. Тем же токеном: GET candidates, simulations, businesses, invitations; GET `/auth/v1/user`.
6. Повторить п. 5 через 1–2 мин (ручная часть — «по времени», в автотест не входит).
7. «Назад» в браузере.
## Ожидаемо
- До выхода: candidates → 200, есть строки (было 3).
- После выхода — сразу и через 1,5 мин: все 4 таблицы → 200 `[]` (доступ к данным закрыт, RLS); `/auth/v1/user` → 403 `session_not_found` (источник: «מה רצוי» «אחרי התנתקות … כל גישה לנתונים עם הטוקן הישן נדחית»; F-05 AC «…כל גישה חוזרת לנתונים מחייבת התחברות מחדש»).
- «Назад» не показывает данные из кэша — экран входа.
