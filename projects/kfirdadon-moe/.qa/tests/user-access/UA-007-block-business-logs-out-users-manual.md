# UA-007 (вручную): блокировка бизнеса сразу выкидывает его вошедших пользователей; вход — «החשבון העסקי אינו פעיל»
- Фича/экран: карточка бизнеса у Super Admin → любой экран бизнеса → /login
- Тикеты: #6a993d7725c79eed60ef15fd (#ef15fd) треб.7; тексты — #92bd0e
- Роль/аккаунт: admin (агент, .qa/auth/admin.json) + менеджер «D» одноразового QA-бизнеса (входит ТОЛЬКО пользователь)
- Устройство: desktop 1440×900
- Тип: негатив
- Предусловия: как AUTH-LG-011 п.1–3 (QA-бизнес, D вступил по ссылке из temp-mail, окно D открыто на дашборде).
## Шаги
1. admin: карточка QA-бизнеса → кнопка блокировки → подтвердить. Ожидаемо: «סטטוס החשבון» «חסום».
2. Пользователь в окне D, без F5: перейти по меню («מועמדים»).
3. Пользователь: ввести почту и пароль D → «כניסה».
4. Контроль автотестом (уже есть): токен менеджера заблокированного бизнеса → 200 [] по candidates/simulations/businesses/invitations (tests/user-access/blocked-business-token.spec.ts).
5. Очистка (с «да» пользователя): разблокировать или удалить QA-бизнес (удаление — см. AUTH-LG-011 п.7–8).
## Ожидаемо
- п.2: сразу /login; плашка «החשבון העסקי אינו פעיל» — «החשבון העסקי שהמשתמש שלכם שייך אליו חסום או נסגר, ולכן לא ניתן להיכנס. לבירור מצב החשבון אפשר לפנות לתמיכה.» + «פנייה לתמיכה»; данных бизнеса на экране нет (источник: треб.7 «חסימת חשבון עסקי מבטלת מיידית את הגישה של כל משתמשיו»).
- п.3: вход отклонён, та же плашка.
## Почему вручную
Нужен вступивший пользователь с паролем и одноразовая блокировка бизнеса. Текст плашки покрыт автотестом AUTH-LG-010; выход со старой сессией — tests/auth-login/blocked-business-support.spec.ts (общий текст, data-reason=unknown).
