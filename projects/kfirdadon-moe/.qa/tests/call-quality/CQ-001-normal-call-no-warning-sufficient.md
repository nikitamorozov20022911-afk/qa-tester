# CQ-001: обычный звонок при нормальной сети — плашки «החיבור חלש» нет, запись «sufficient»
- Фича/экран: официальный звонок «הניסיון הרשמי» (S-16) → отчёт кандидата (get_candidate_report, «מצב טכני»)
- Тикеты: #51da2a (b28a22ed6a85bb764151da2a)
- Роль/аккаунт: business (кандидат link_only) + кандидат (гость, Chrome с фальшивым микрофоном .qa/audio/seller-dialog.wav)
- Устройство: кандидат — Chrome 390×844; business — desktop 1440×900
- Тип: позитив; @call — тратит OpenAI (≈1,5–2 мин голоса); НЕ prod-safe (кандидат «QA-AUTO-CQ-CALL-…», официальная попытка использована)
- Предусловия: активная симуляция «מערכות סולאריות»; обычная сеть тестовой машины (14.10: RTT ~155 мс).
## Шаги
1. business: /candidates/new → кандидат, канал «רק ליצור קישור» → ссылка /c/…
2. Кандидат: вступление → согласие → тех. проверка → «לדלג ישר לשיחה הרשמית» → флажок → «מוכן, מתחילים».
3. Дождаться таймера и статуса «מחובר · הלקוח מקשיב» / «הלקוח מדבר»; говорить ~90 с (файл микрофона).
4. «לסיים שיחה» → «לאשר סיום שיחה» → «הסימולציה הושלמה».
5. business: get_candidate_report → recording.quality_status.
## Ожидаемо
- За весь звонок плашка «החיבור חלש כרגע. השיחה ממשיכה, אבל ייתכן שהקול ייקטע.» ни разу не появилась; событие connection_warning не отправлялось (источник: AC «שיחה תקינה בחיבור רגיל נשמרת … ובלי התרעת חיבור קבועה»; Figma 633:987 — обычный звонок без плашки).
- recording.quality_status = «sufficient», не «degraded» (источник: AC «…נשמרת עם איכות הקלטה מספקת»; F-36 треб.7).
- В end-candidate-attempt уходит recording_quality {input_level, packet_loss, latency_ms}; packet_loss ≤ 0,2 (источник: «מצב נדרש» — «איכות ההקלטה נמדדת לפי מה שנלכד בפועל»).
- Вариант тикета «RTT ~450 мс»: переменная QA_CALL_FORCE_RTT_MS=450 подменяет RTT в getStats на настоящем звонке — ожидаемое то же (см. CQ-004: серверная сторона при RTT 450 вручную не проверялась).
