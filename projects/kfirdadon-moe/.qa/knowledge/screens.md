# Screens (מסכים) — סימולטור AI למועמדים למשרות מכירה

Источник: вкладка «מפרט» в mifrat (https://mifrat.com/Project?id=6a6a1878b4208f018469d071&tab=spec), извлечено 2026-10-04.
- Поля (название, תיאור, עדיפות, סיפור משתמש, AC) — режим «עבודה», форма «ערוך תכונה» (закрыта через «ביטול», ничего не сохранялось).
- Модуль, номер пункта, «תלויות וקשרים» — режим «ספר», פרק «תכונות ופריטים» (страница пункта «מסך · MODULE»). AC в обоих режимах совпадают.
- «Используется в תהליכי משתמש» — режим «ספר», раздел «תהליכי משתמש»: шаги (שלבי התהליך), у которых указан этот экран.
- Всего экранов (סוג פריט «מסך»): 22 — совпадает со сводкой «מפת המסמך».
- Отдельного поля «элементы экрана» в «מפרט» нет: элементы известны только из текста תיאור и AC. Роли — только из User Story («בתור …») и AC; отдельного поля ролей у экрана нет.
- Состояния — дословно из блока «מצבי המסך» в תיאור. Если состояние (пусто/загрузка/ошибка/успех) не названо — его в документации нет.
- Назначение = первый абзац תיאור; во всех 22 экранах он дословно совпадает с полем «סיפור משתמש».
- Приоритет: у S-06 в форме «כדאי», в режиме «ספר» «חשוב» (одно и то же значение should).

## S-01 — ניהול בתי העסק (Super Admin)

- **Источник:** «מפרט» → תכונות ופריטים, פריט 05 (מסך · PLATFORM_ADMIN)
- **Модуль:** platform_admin
- **Приоритет:** חובה

- **Роли:** מנהל מערכת ראשי (Super Admin)
- **Состояния (מצבי המסך):**
  - כניסה — מתפריט ה-Super Admin לאחר התחברות.
  - יציאה — יצירת עסק מפיקה קישור הזמנה למנהל החשבון הראשון.
  - מצב ריק — פלטפורמה ללא בתי עסק מציגה הסבר שההקמה ידנית בלבד וכפתור ראשי.
  - מצב שגיאה — שדה חובה חסר חוסם שמירה ומסומן במקומו; כשל בהפקת הקישור מאפשר הפקה חוזרת מבלי ליצור עסק כפול.
  - מצב טעינה — нет данных.
- **AC:**
  1. ניהול מחזור חיי חשבון עסקי: יצירה עם שדות מוגדרים, צפייה בפרטים ובמשתמשים, חסימה ומחיקה, והפקת קישור הזמנה למנהל החשבון הראשון.
  2. לא תתאפשר הרשמה עצמאית של בתי עסק ב-MVP; כל חשבון נפתח על ידי Super Admin בלבד.
  3. עברית היא שפת ברירת המחדל של הפיילוט.
  4. בידוד נתונים מלא בין בתי עסק.
  5. גישת Super Admin למידע מועמדים מוגבלת לתמיכה ומתועדת ברישום גישה.
- **תלויות וקשרים:**

- **Используется в תהליכי משתמש:** 1 «הקמת חשבון עסקי חדש והפקת הזמנה למנהל החשבון הראשון» — שלב 01; 2 «החלת תבנית סימולציה על עסק חדש» — שלב 01; 52 «המסע המרכזי מהקמת העסק ועד החלטת הגיוס» — שלב 01; 58 «הגדרת מסגרת הפיילוט וניטור היקפו» — שלב 01

## S-02 — מסך תמיכה ותפעול (Super Admin)

## S-06 — הגדרות העסק והמכסה

- **Источник:** «מפרט» → תכונות ופריטים, פריט 16 (מסך · IDENTITY_ACCESS)
- **Модуль:** identity_access
- **Приоритет:** כדאי (в режиме «ספר» — חשוב)
- **Назначение / User Story:** בתור מנהל חשבון עסקי אני רוצה לעדכן את פרטי העסק, להזין את הנוסח המשפטי שיוצג למועמדים ולראות את מצב המכסה שלי, כדי שהמידע והנוסח המוצגים למועמדים יהיו נכונים ושאדע כמה סימולציות נותרו.
- **Роли:** מנהל חשבון עסקי (AC 5: מסך ההגדרות פתוח למנהל חשבון בלבד ואינו זמין למנהל מגייס)
- **Элементы (из תיאור):** המסך מחזיק שלושה אזורים: פרטי העסק ושפת ברירת המחדל, שדה טקסט חופשי לנוסח המשפטי הקבוע שיוצג למועמדי העסק, ונתוני המכסה והצריכה.
- **Состояния (מצבי המסך):**
  - כניסה — מתפריט ההגדרות. המסך מחזיק שלושה אזורים: פרטי העסק ושפת ברירת המחדל, שדה טקסט חופשי לנוסח המשפטי הקבוע שיוצג למועמדי העסק, ונתוני המכסה והצריכה.
  - יציאה — שמירה מחזירה לדשבורד עם הפרטים המעודכנים; עדכון הנוסח דורס את הקודם ואינו יוצר גרסה חדשה.
  - מצב ריק — ללא מכסה מוגדרת מוצג רק נתון הצריכה ללא חסימה; נוסח משפטי שטרם הוזן מוצג כשדה ריק עם הסבר שמסלול המועמד ייחסם בלעדיו.
  - מצב שגיאה — שדה חובה שנמחק חוסם שמירה ומסומן ליד השדה תוך שמירת שאר הערכים.
  - מצב טעינה — нет данных.
- **AC:**
  1. מנהל חשבון עסקי מקבל הרשאות ניהול מלאות ברמת העסק, כולל עדכון פרטי העסק.
  2. הזנת נוסח משפטי קבוע חד-פעמי שיוצג למועמדי העסק במסך הפרטיות וההסכמה, ללא ניהול גרסאות.
  3. הגדרת שפת ברירת המחדל של העסק, כאשר עברית היא ברירת המחדל בפיילוט.
  4. הצגת מכסת הסימולציות, הצריכה בפועל והיתרה — הנחת עבודה זמנית הכפופה להחלטה מסחרית לאחר הפיילוט.
  5. מסך ההגדרות פתוח למנהל חשבון בלבד ואינו זמין למנהל מגייס.
- **תלויות וקשרים:**
  - קשור ל: 11 בקרת גישה מבוססת תפקיד ובידוד נתונים בין בתי עסק
