# תהליכי משתמש (flows)

- **Проект:** סימולטור AI למועמדים למשרות מכירה
- **Источник:** вкладка «מפרט» в mifrat — https://mifrat.com/Project?id=6a6a1878b4208f018469d071&tab=spec, раздел ד «תהליכי משתמש» (58 תהליכים). PDF нет.
- **Как извлечено (2026-10-04):** режим «עבודה» → список «תהליכים (58)» → форма каждого процесса (поля «שם התהליך», «תיאור התהליך», «שלבי התהליך»). Экран для каждого шага взят из режима «ספר» («תהליך משתמש · N / 58»): там под текстом шага указано название экрана. Тексты шагов в обоих режимах совпадают дословно (проверено для всех 58).
- **Структура данных в источнике:** у процесса есть только название, описание (у всех 58 поле «תיאור התהליך» пустое) и шаги. В каждом шаге четыре части: «כניסה» / «יציאה» / «מצב ריק» / «מצב שגיאה» + экран. Отдельных полей «триггер», «успех», «сбои» и «роль/персона» в документе нет. Поэтому ниже: триггер — это «כניסה» шага 1, успех — «יציאה» последнего шага, сбои и блокировки — «מצב שגיאה» каждого шага. Роль в форме процесса не указана, она видна только из текста шагов.
- **Всего:** 58 процессов (FL-01 … FL-58). Номер FL совпадает с номером процесса в «מפרט».

## FL-01. הקמת חשבון עסקי חדש והפקת הזמנה למנהל החשבון הראשון

- **Источник:** «מפרט» → ד «תהליכי משתמש», תהליך 1/58 (режим «עבודה»: תהליכים (58) → «הקמת חשבון עסקי חדש והפקת הזמנה למנהל החשבון הראשון»; экраны по шагам — режим «ספר», «תהליך משתמש · 1 / 58»)
- **שם התהליך:** הקמת חשבון עסקי חדש והפקת הזמנה למנהל החשבון הראשון
- **תיאור התהליך:** поле пустое в форме
- **Триггер:** שלב 1 → «כניסה»
- **Успех:** שלב 2 → «יציאה»
- **Сбои/блокировки:** «מצב שגיאה» каждого шага
- **Экраны:** ניהול בתי העסק (Super Admin) · ניהול משתמשים והזמנות בעסק

### שלבי התהליך

**שלב 1** — מסך: ניהול בתי העסק (Super Admin)
- כניסה: Super Admin מתחבר ומגיע לרשימת בתי העסק, ולוחץ על יצירת עסק חדש לאחר שנסגרה עסקה מול בית עסק.
- יציאה: לאחר מילוי כל שדות החובה ושמירה, נוצרת רשומת העסק ומוצג קישור ההזמנה למנהל החשבון הראשון להעתקה.
- מצב ריק: פלטפורמה ללא בתי עסק מציגה הסבר שהקמה מתבצעת ידנית בלבד וכפתור ראשי ליצירת העסק הראשון.
- מצב שגיאה: שדה חובה חסר חוסם שמירה ומסומן במקומו; כשל בהפקת הקישור מציג הודעה ומאפשר הפקה חוזרת מבלי ליצור עסק כפול.

**שלב 2** — מסך: ניהול משתמשים והזמנות בעסק
- כניסה: לאחר יצירת העסק, Super Admin נכנס לרשימת המשתמשים שלו כדי לוודא שההזמנה למנהל החשבון הראשון בסטטוס ממתינה.
- יציאה: ההזמנה מוצגת כממתינה; לאחר שמנהל החשבון משלים הצטרפות היא עוברת לסטטוס פעיל וההקמה מסתיימת.
- מצב ריק: עסק שזה עתה הוקם מציג טבלת משתמשים ריקה עם ההזמנה הממתינה היחידה והסבר מה יקרה כשתתקבל.
- מצב שגיאה: כשל בשליחת מייל ההזמנה מסמן את ההזמנה ומציע שליחה חוזרת או העתקת הקישור לערוץ אחר, כדי שההקמה לא תיתקע.


## FL-02. החלת תבנית סימולציה על עסק חדש

- **Источник:** «מפרט» → ד «תהליכי משתמש», תהליך 2/58 (режим «עבודה»: תהליכים (58) → «החלת תבנית סימולציה על עסק חדש»; экраны по шагам — режим «ספר», «תהליך משתמש · 2 / 58»)
- **שם התהליך:** החלת תבנית סימולציה על עסק חדש
- **תיאור התהליך:** поле пустое в форме
- **Триггер:** שלב 1 → «כניסה»
- **Успех:** שלב 2 → «יציאה»
- **Сбои/блокировки:** «מצב שגיאה» каждого шага
- **Экраны:** ניהול בתי העסק (Super Admin) · עורך הסימולציה — הגדרת התרחיש

### שלבי התהליך

**שלב 1** — מסך: ניהול בתי העסק (Super Admin)
- כניסה: Super Admin בוחר עסק חדש שביקש סיוע בהקמת התרחיש הראשון ופותח עבורו את ספריית התבניות.
- יציאה: נבחרת תבנית מתאימה לתחום הפעילות של העסק והיא מוחלת כטיוטת סימולציה חדשה בחשבון שלו.
- מצב ריק: ספרייה ללא תבניות מציגה הסבר קצר מה תבנית מכילה וכפתור ליצירת התבנית הראשונה.
- מצב שגיאה: כשל בהחלת התבנית מציג הודעה עם ניסיון חוזר ואינו יוצר טיוטה חלקית בחשבון העסק.

**שלב 2** — מסך: עורך הסימולציה — הגדרת התרחיש
- כניסה: הטיוטה שנוצרה מהתבנית נפתחת בעורך הסימולציה עם כל השדות מלאים ומסומנים כניתנים לעריכה.
- יציאה: מנהל החשבון העסקי ממשיך מכאן בעצמו — מתאים את השדות למציאות שלו וממשיך לשלב הפקת הטיוטה.
- מצב ריק: שדות שהתבנית לא כיסתה — כמו מחיר או קשר קודם — נותרים ריקים עם טקסט הסבר, ולא מולאו בערכים גנריים.
- מצב שגיאה: ניסיון של מנהל חשבון עסקי לערוך את התבנית עצמה ולא את העותק נחסם עם הסבר שהתבנית מנוהלת ברמת הפלטפורמה.


## FL-03. טיפול תמיכה בניסיון תקול מקצה לקצה

- **Источник:** «מפרט» → ד «תהליכי משתמש», תהליך 3/58 (режим «עבודה»: תהליכים (58) → «טיפול תמיכה בניסיון תקול מקצה לקצה»; экраны по шагам — режим «ספר», «תהליך משתמש · 3 / 58»)
- **שם התהליך:** טיפול תמיכה בניסיון תקול מקצה לקצה
- **תיאור התהליך:** поле пустое в форме
- **Триггер:** שלב 1 → «כניסה»
- **Успех:** שלב 2 → «יציאה»
- **Сбои/блокировки:** «מצב שגיאה» каждого шага
- **Экраны:** מסך תמיכה ותפעול (Super Admin) · דוח המועמד

### שלבי התהליך

**שלב 1** — מסך: מסך תמיכה ותפעול (Super Admin)
- כניסה: פנייה של מועמד או התרעת ניסיון עם תקלה בדשבורד מובילות את Super Admin למסך התמיכה התפעולי, מסונן לניסיונות תקולים.
- יציאה: לאחר זיהוי השלב שבו נעצר הניסיון מתבצעת פעולת התיקון המתאימה — איפוס ניסיון עם סיבה, הארכת תוקף או הפעלת עיבוד מחדש.
- מצב ריק: כשאין ניסיונות תקולים בטווח הנבחר מוצג מצב ריק חיובי עם אפשרות להרחיב את טווח התאריכים.
- מצב שגיאה: פעולת תמיכה שנכשלה מציגה מה נכשל ומה הפעולה הבאה, והרשומה נותרת בסטטוסה הקודם ללא שינוי חלקי.

**שלב 2** — מסך: דוח המועמד
- כניסה: כאשר האבחון מחייב עיון בתוכן, Super Admin פותח את הדוח לאחר בחירת סיבת גישה מתוך רשימה סגורה.
- יציאה: לאחר האימות הסטטוס הטכני מתעדכן, המגייס מקבל דוח תקין, ורישום הגישה נשמר כראיה שהחשיפה הייתה מוצדקת.
- מצב ריק: דוח שעדיין בעיבוד מציג מה כבר קיים — ההקלטה נשמרה — מה עדיין רץ והערכת זמן, במקום מסך ריק.
- מצב שגיאה: דוח בשגיאה מציג ל-Super Admin פעולת הפעלה מחדש של העיבוד; כשל חוזר מסמן את הרשומה לטיפול ידני ומציג את הלוג האחרון.

### שלבי התהליך

**שלב 1** — מסך: מסך תמיכה ותפעול (Super Admin)
- כניסה: Super Admin מבקש לפתוח דוח, תמלול או הקלטה של מועמד במסגרת טיפול בפנייה או בבקרת איכות.

- מצב שגיאה: ניסיון לפתוח תוכן ללא בחירת סיבה נחסם, וההסבר מציין שהגישה מוגבלת לתמיכה, בקרת איכות או טיפול מורשה בלבד.

**שלב 2** — מסך: דוח המועמד
- כניסה: הדוח נפתח לאחר בחירת הסיבה, ובמקביל נרשמת רשומת גישה עם זהות המשתמש, המועמד, סוג התוכן, הסיבה וחותמת הזמן.
- יציאה: בסיום הצפייה רישום הגישה נותר זמין לבדיקה מאוחרת ומשמש ראיה בעת טיפול בבקשת עיון או מחיקה של המועמד.
- מצב ריק: כאשר טרם בוצעה גישה כלשהי לרשומה, רישום הגישה שלה מוצג ריק עם הסבר שאיש עדיין לא עיין בתוכן.
- מצב שגיאה: ניסיון לערוך או למחוק רשומת גישה נחסם; רישום הגישה בלתי ניתן לשינוי גם על ידי מי שנרשם בו.
