# SEC-001: REVOKE — client не может писать защищённые колонки wallets / deals / users (PostgREST → 403)
- Фича/экран: безопасность БД (Supabase / PostgREST), без UI
- Тикеты: #6a9e9592f020cfee7fb9cb5e
- Роль/аккаунт: client (0500000004), сессия `.qa/auth/client.json`
- Устройство: desktop (API-тест)
- Тип: негатив / безопасность
- Предусловия: `apikey` и `authorization` (JWT пользователя) — из первого запроса страницы к `/rest/v1/`; у client есть кошелёк и хотя бы одна сделка
## Шаги
1. Прочитать свой кошелёк, свою сделку и свою строку users (GET).
2. PATCH текущими значениями (ничего не меняется даже при успехе): `wallets.available_balance`, `escrow_balance`, `awaiting_release_balance`; `deals.money_state`, `cancellation_requested_by`, `payer_id`, `payee_id`; `users.kyc_status`, `phone`.
3. POST `deals` с `money_state` и отдельно с `cancellation_requested_by` (payer_id/payee_id — несуществующий uuid).
4. Повторно прочитать кошелёк.
## Ожидаемо
- Каждый PATCH/POST → HTTP 403, код 42501 «permission denied for table …» (AC 1–4: «שלושת שדות היתרה… money_state ו-cancellation_requested_by… לא ב-UPDATE ולא ב-INSERT… payer_id/payee_id… kyc_status ו-phone אינם ניתנים לכתיבה»; коммент программиста 01.10 — 403/42501)
- Баланс кошелька после попыток не изменился
