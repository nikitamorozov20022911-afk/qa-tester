Источник: брифы `.qa/research/<hash>.md`; тикеты #88acb5, #1388e0, #d9877d, #36b4d7, #c70f72 (עבר QA 17.11.2026, проверил пользователь).
Аккаунты: `client` = 0500000004 (менеджер, личная карта + общие кошельки), `client2` = 0500000003 (ребёнок «נגה ברק»), `provider` = 0500000005 (участник общего кошелька «QA-ארנק משותף 03.10», id в `QA_SHARED_WALLET_ID`, по умолчанию `3bf0fc53-2b78-46d2-9f53-f824c57ceb39`).
Цифры временные, выдаются сервером (Wallet.cardLast4, решение владельца 16.11) → проверяем формат `/^[\u200e\u200f]?•••• •••• •••• \d{4}$/` и совпадение между экранами, не значения. Полный 16-значный номер нигде не показывается.
Всё — только просмотр, новые кошельки не создаются → `@prod-safe`. Код: `tests/cards/*.spec.ts`, общие помощники — `tests/cards/helpers.ts`.
Не автоматизируется: пункт «новая карта сразу показывает цифры» (#d9877d AC2 — нужен новый кошелёк), «полный номер не хранится» (код/БД), Android-пустой экран vc4 (нативная сборка).

**Expected:**
- цифры в «ביצוע תשלום» = цифры карточки в «כל הכרטיסים» (AC1)
- цифры одинаковы после перезагрузки на обоих экранах (AC3: сохраняются в Wallet.cardLast4)
- на страницах нет 16-значного номера (AC3, только то, что видно в UI)
