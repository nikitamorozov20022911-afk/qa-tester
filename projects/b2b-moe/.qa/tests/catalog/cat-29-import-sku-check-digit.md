# cat-29: импорт из Excel — контрольная цифра מק"ט (EAN-8 / UPC-A / EAN-13) в предпросмотре и подтверждение перед записью
- Фича/экран: F-01 «ניהול קטלוג מוצרים» · /catalog/import «ייבוא מוצרים מאקסל» (предпросмотр, окно подтверждения)
- Тикеты: #dc1afa (9d0261f3f435f180ebdc1afa; commits 40416f0, 01d9e35; עבר QA 29.10). Правило и эталон текста — #1ee7e8 (cat-26).
- Роль/аккаунт: admin (jleprog34@gmail.com; при параллельной проверке — admin-2)
- Устройство: desktop 1440×900
- Тип: негатив + граница + позитив + регресс
- Предусловия: CSV `שם מוצר,מחיר,מק"ט`, имена `QA-AUTO-dc1afa-<ts>-*`, коды EAN — уникальные, от метки времени (префикс 2x), неверный = верный с +1 в контрольной. Колонки распознаются по таблице — модель (import-map) не нужна. Реальный импорт — только своих QA-AUTO строк, удалить после.
## Шаги
1. /catalog/import → CSV с одной строкой: EAN-13 с неверной контрольной.
2. В ячейке מק"ט исправить последнюю цифру; затем снова испортить; снова исправить → «ייבוא מוצר אחד».
3. CSV: неверные EAN-8, UPC-A, EAN-13 (последняя цифра), EAN-13 (ошибка в середине); верные EAN-8 / UPC-A / EAN-13; 5 цифр, 14 цифр, ABC123, внутренний QA-AUTO-X.
4. Клик по счётчику «ספרת ביקורת שגויה: N» (отмеченная строка ниже экрана).
5. «ייבוא N מוצרים» → окно → «תיקון המק"טים».
6. CSV из 3 неверных → корзина «הוצאת שורה 1» → «ייבוא» → окно. CSV «неверный + внутренний» → убрать неверный → «ייבוא».
7. CSV: מק"ט уже есть в каталоге; один верный מק"ט дважды в файле.
8. CSV с одной своей неверной строкой → «ייבוא» → «ייבוא בכל זאת» → открыть товар в «עריכת מוצר». Удалить товар.
## Ожидаемо
1. Ячейка מק"ט — aria-invalid=true, красная; под строкой «ספרת הביקורת של הברקוד שגויה — בדקו את הספרות» (та же надпись, что в форме товара); сверху счётчик «ספרת ביקורת שגויה: 1» («מה רצוי»: «מסומן בתצוגה המקדימה באותה הודעה כמו בטופס המוצר»).
2. Исправление снимает отметку и счётчик; порча возвращает; верный код — импорт без окна (POST products с этим מק"ט) («מה רצוי»: «יכול לתקן»).
3. Отмечены ровно 4 строки (8/12/13 цифр с неверной контрольной, в т.ч. ошибка в середине), счётчик 4; верные, 5/14 цифр, буквы и внутренний код — без отметки («מה רצוי»: «מק"ט באורך 8 / 12 / 13 ספרות»).
4. Страница прокручивается к первой отмеченной строке (коммент программиста).
5. Окно «לייבא 4 מק"טים עם ספרת ביקורת שגויה?», текст «ספרת הביקורת של הברקוד שגויה — בדקו את הספרות: <коды>…», кнопки «תיקון המק"טים» / «ייבוא בכל זאת»; до подтверждения — 0 запросов записи; «תיקון» закрывает окно, отметки остаются («מה רצוי»: «לאשר מפורשות לפני הייבוא»). Для одного кода — «לייבא מק"ט עם ספרת ביקורת שגויה?» / «תיקון המק"ט».
6. После удаления строки счётчик 2, окно «לייבא 2 מק"טים…» без удалённого кода; когда отмеченных нет — «ייבוא» без окна, отправлена только оставшаяся строка.
7. Как до фикса: «קיים בקטלוג — ידולג» (счётчик «ידולגו: 1»), повтор в файле — «מק"ט כפול בגיליון» (F-01 / S-02 регресс).
8. До «ייבוא בכל זאת» — 0 запросов; после — POST products 201, מק"ט записан как есть; в «עריכת מוצר» под מק"ט та же надпись.
## Не автоматизируется
- 390 px (вид надписи под строкой и окна на телефоне) — проверено вручную при тесте, в автотест не входит (тикет про десктоп).
- Наблюдение при записи автотеста (29.10): если загрузить файл до того, как экран получил список מק"ט каталога (`products?select=sku`), существующий מק"ט показывается «חדש», а не «קיים בקטלוג — ידולג». Человек так быстро не успевает; автотест ждёт загрузку списка. Не часть тикета.
