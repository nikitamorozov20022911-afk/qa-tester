# Снимок логики остатка (מלאי) — состояние на 2026-10-26

Сайт: https://b2b-tau-five.vercel.app/ · бандл на момент снимка `assets/index-BwZ3D1XM.js` · снимок собран из файлов .qa + живой проверки «только чтение» 26.10 (≈19:00).

## 1. Зачем этот снимок
- 26.10 клиент попросил **временно** отключить ограничения по остатку: товары с остатком 0 должны заказываться и продаваться.
- Потом логику надо вернуть **ровно как сейчас**. Ниже — что именно сейчас работает, где, с какими текстами и какими серверными проверками, кто это ввёл и какие кейсы/автотесты это проверяют.
- Прецедент: 14.10 и 19.10 владелица уже временно разрешала продажу без остатка в «מכירה מיידית» — тогда было только предупреждение «X יימכרו ללא מלאי» / «אין מלאי — המכירה תירשם בכל זאת» (research/80bb3c.md:112, :180). 20.10 пользователь это отменил (context.md:71). Этот режим — образец того, как может выглядеть временная отмена.

## 3. Текущее поведение по местам

### 3.1 Каталог клиента `/shop` (карточки и страница товара `/shop/p/<id>`)
- **Видимость**: видны все неархивные товары, включая «זמינות» выкл. и остаток 0 (`customer_catalog_count` = 755 = все товары). Категория только с «לא זמין» товаром — видна (co-21, #899df3e5; research/157fed2c.md:68). Сортировка по умолчанию: сначала товары в наличии.
- Товар с остатком 0 (или «זמינות» выкл., или остаток < минимума): на карточке бейдж «אזל», кнопки «הוספה לעגלה — <товар>» НЕТ. На странице товара: метка «אזל מהמלאי», кнопка «המוצר אזל מהמלאי» disabled, «הוספת יחידה»/«הפחתת יחידה» disabled. Живое 26.10: «אל די אדום קצר» (0 шт., мин. 2) и «QA-AUTO-6cdf-1410» (זמינות выкл., 1 шт.) — оба так.
- Товар в наличии: метка «במלאי», кнопка «הוסף לעגלה ₪…», без предупреждений. Текста «כמות מוגבלת» нигде нет — только два состояния «במלאי»/«אזל» (#6a748c9a, co-05; research/backfill/client-ordering.md:13-14).
- Счётчик на странице товара ограничен доступным остатком: «אלור אפור» (stock_qty 3) — после 3 «הוספת יחידה» disabled и текст «זו הכמות המקסימלית שניתן להזמין כרגע» (живое 26.10, скрин `screenshots/stock-snapshot-1026-shop-product-plus-cap-3-desktop.png`).
- Фильтр «סינון ומיון» → «זמינות»: «הכל» / «במלאי בלבד» (параметр `p_in_stock` в `customer_catalog`/`customer_catalog_count`) — co-22, co-26, #157fed2c, #8103a9.
- «מוצרים אחרונים» (#8103a9), «הזמן שוב» (#aef12a), рекомендации (`customer_recommendations`; текст настроек «מלאי, זמינות ומחיר הלקוח נבדקים בזמן הצפייה — מוצר שאזל לא יוצג בהמלצות גם אם הוא מופיע כאן.») используют ту же проверку. «הזמן שוב»: недоступный/«אזל» товар не добавляется, сообщение с именем («אזל מהמלאי — לא ייכנס לעגלה.»; co-30, research/aef12a.md:44,77).
- Источник: F-04 AC (features.md:87-105), F-05/F-33 «מוצר שאזל משפיע על זמינותו», D-15 (decisions.md:117-122), #6a748c9a, #6a38cf5e (cat-11), живая проверка.

### 3.2 Корзина `/shop/cart`
- «+» в строке disabled, когда кол-во = доступному остатку (живое 26.10: «מצית קליפט», «דוידוף גולד» при stock_qty 1 — «הוספת יחידה» disabled; «ווינסטון אקווה» stock 6 — активна). Отдельного текста в корзине при этом нет. Скрин `screenshots/stock-snapshot-1026-cart-plus-disabled-at-stock-desktop.png`. Норма по решению 26.10 (context.md:79, :93).
- Если в корзине кол-во больше доступного (остаток упал) — строка помечается «הכמות בעגלה חורגת מהזמין במלאי» + действие «עדכנו לכמות הזמינה» (тексты из бандла; вживую не воспроизводилось — нужен уход остатка). Отмечено как «в корзине кол-во над остатком помечается» в research/6a98bd.md:5.
- Товар стал «אזל»/недоступен, а лежит в корзине: «פריט שאזל מהמלאי נמצא בעגלה. יש להסיר אותו כדי להמשיך לביצוע ההזמנה.» — «המשך לביצוע הזמנה» блокируется (F-06 AC5, D-15, co-09 — ручной кейс, не проверялся).
- Резерва корзина не делает (context.md:79).

### 3.3 Оформление заказа `/shop/checkout` → `rpc/place_order`
- На экране «ביצוע הזמנה» отдельной проверки остатка не видно (живое 26.10). Блок при «אזל» в корзине: «פריט שאזל מהמלאי נמצא בעגלה. יש להסיר אותו מהעגלה כדי לשלוח את ההזמנה.» (бандл).
- Сервер: клиент разбирает ошибки `place_order` с кодами `UNAVAILABLE:<товар>` → «המוצר "<товар>" אזל מהמלאי. הסר אותו מהעגלה כדי להמשיך.» и `INSUFFICIENT_STOCK:<товар>:<N>` → «הכמות המבוקשת מהמוצר "<товар>" אינה זמינה יותר במלואה. עדכן את הכמות בעגלה ונסה שוב.», также `BELOW_MIN_ORDER`. Значит сервер `place_order`, судя по коду клиента, отклоняет заказ сверх доступного остатка и недоступные товары. **Вживую не проверено** (заказ не оформлялся).

### 3.4 «מכירה מיידית» `/orders/walk-in` → `rpc/walkin_products`, `rpc/create_walkin_order`
- Подзаголовок: «מכירה בקופה — בחר מוצרים ולחץ «רישום המכירה» כדי לבחור לקוח ולאשר. הכמות יורדת מהמלאי מיד עם האישור.»
- Поиск (`walkin_products` возвращает `available`, `sellable`): товар с доступным остатком — пункт «<товар> נותרו N ₪…»; остаток 0 — пункт «<товар> אזל מהמלאי ₪…» disabled, клик не добавляет (живое: «אל די אדום קצר», «אלור מנטה/סגול/תפוח»). Товар «זמינות» выкл. — сервер его возвращает, но клиент в списке не показывает: «לא נמצאו מוצרים זמינים התואמים לחיפוש.» (живое: «נקש»; «QA-AUTO-6cdf-1410» даже с остатком 1).
- מק"ט/имя + Enter: остаток 0 → «<товар> — אזל מהמלאי.» (ord-21, #5711c3); «זמינות» выкл. → «QA-AUTO-6cdf-1410 אינו זמין למכירה.» (живое 26.10).
- Строка: «+» останавливается на остатке, под строкой «זו כל הכמות במלאי (N)»; ввод больше остатка → поле invalid + alert «במלאי N בלבד — לא ניתן למכור יותר» (живое: «אלור אפור», N=3, ввод 5; скрин `screenshots/stock-snapshot-1026-walkin-qty5-over-stock3-desktop.png`). «רישום המכירה» при неверном кол-ве → баннер «הכמות של <товар> אינה תקינה. עדכן אותה ונסה שוב.», окно подтверждения не открывается (ord-26). Остаток упал после добавления → «נותרו N יחידות בלבד מ־<товар>. עדכן את הכמות ונסה שוב.».
- Сервер: `create_walkin_order` → 400 `INSUFFICIENT_STOCK` при строке сверх остатка (#80bb3c, research/80bb3c.md:170-175; research/929aa5.md:5). Предупреждения «יימכרו ללא מלאי» удалены.
- Решение: 20.10 «нельзя продать больше, чем есть» (context.md:71); требование #6a7496de «לא יהיה ניתן למכור כמות גדולה יותר מהכמות הזמינה במלאי» (research/backfill/orders.md:13).

### 3.5 «עריכת הזמנה» `/orders/<id>/edit` → `rpc/order_edit_products`, `rpc/update_order_items`
- Лимит строки = `sellable` из `order_edit_products` = במלאי − резерв других заказов. Живое 26.10, заказ #490 («ממתינה לאישור», «מצית קליפט» ×2): sellable 3 → «+» с 2 до 3, затем disabled; ввод 7 + Tab → поле invalid + alert «במלאי 3 בלבד — לא ניתן להזמין יותר» (скрин `screenshots/stock-snapshot-1026-order490-edit-qty7-over-3-desktop.png`). Выход «ביטול» — заказ остался «מצית קליפט 2 ₪5.00 ₪10.00», `update_order_items` не вызывался.
- Поиск добавления: товары с остатком 0 показаны в списке без метки (в отличие от walk-in), но по клику — alert «אין מלאי זמין ל<товар>.» и строка не добавляется (живое: «אלור מנטה»). Сверх остатка из поиска — «במלאי N בלבד מ<товар> — לא ניתן להוסיף עוד.» (ord-27). «זמינות» выкл. — не показан: «לא נמצאו מוצרים זמינים התואמים לחיפוש.» (живое: «נקש»).
- Строка, уже превышающая остаток при открытии: красная, «במלאי N בלבד — יש להקטין את הכמות ל־N לכל היותר» / «אין מלאי זמין — יש להסיר את הפריט»; «שמור שינויים» не сохраняет (#6a98bd, research/6a98bd.md:82; research/929aa5.md:5).
- Сервер: `update_order_items` → 400, code `22023`, message `INSUFFICIENT_STOCK:<товар>:<N>`; на экране «הכמות של <товар> גדולה מהמלאי (N). עדכן אותה ונסה שוב.» / при N=0 «אין מלאי זמין ל<товар>. הסר את הפריט ונסה שוב.» (#929aa5, commit 26ec00e, миграция `20261025100000_an_order_edit_cannot_pass_the_shelf.sql`; ord-37).
- Решения: 20.10 (context.md:71), 25.10 (context.md:78), 26.10 (context.md:79).

### 3.6 «הזמנה מהודעה» `/orders/new` → `rpc/customer_order_products`, `rpc/create_customer_order` (вживую не проверялось)
- Экран admin/נציג: вставить сообщение/фото клиента → черновик заказа. По бандлу: товар «אזל» в черновике — «אזל מהמלאי · לא ניתן להוסיף להזמנה» / «אזל מהמלאי — לא ייכנס להזמנה.»; ошибки сервера `create_customer_order`: `UNAVAILABLE` → «המוצר "<товар>" אזל מהמלאי. הסר את השורה ונסה שוב.», `INSUFFICIENT_STOCK` → «נותרו N בלבד מ־"<товар>". עדכן את הכמות ונסה שוב.». В кейсах .qa этого экрана нет — при временной отмене **не забыть** и его.

### 3.7 Утверждение заказа `rpc/approve_order`
- F-35 AC3 / D-22 (decisions.md:167-172): при утверждении сверх остатка — **предупреждение**, не блок. В коде клиента для approve_order кода про остаток нет (только `EMPTY_ORDER`, `INVALID_STATUS_TRANSITION` …) → вероятно, проверки нет. Не проверялось (вне ограничений, которые вводились).

### 3.8 ליקוט (сбор) — «לוקט»/«חסר», `rpc/mark_pick_line`
- Списание «במלאי» только при «לוקט» (#6a7494e8, inv-05). Если в ячейке меньше, чем в строке: «בתא <код> רשומות N יחידות בלבד. סמנו «חסר» עם הכמות שנלקטה בפועל.» (`INSUFFICIENT_STOCK` в mark_pick_line, бандл). Товар «ללא מיקום» можно отмечать «לוקט» без проверки остатка (context.md:69, решение 18.10).
- Это **физическое** ограничение склада, не продажное. При временной отмене оно останется: заказ на товар без остатка дойдёт до ליקוט и потребует «חסר» (если товар в месте) — учесть в объяснении клиенту.

### 3.9 Карта склада / возврат поставщику / перемещения
- «החזרה לספק»: кол-во ≤ остатка в месте/«ללא מקום», ошибки «ב<место> יש N יחידות בלבד.» / «ללא שיוך למקום יש N יחידות בלבד.» / «אין מלאי של הפריט להחזרה.» (#1f62ca42, #9301886c; wm-16, wm-19, wm-20). Перемещение: «במקום X זמינות N בלבד.». Это ограничения физического склада — к продаже не относятся, отключать не нужно.
- Место с товаром 0 не «ריק» (#d9258e0b), «הסרה מהמקום» строки 0 (#aea5d4) — не зависят от продажных ограничений.

### 3.10 Уведомления о низком остатке
- Отдельного экрана/уведомлений нет (маршрутов нет в бандле; F-34/S-34 не реализованы). Есть только статусы «מלאי נמוך»/«אזל» и плитки в `/catalog` (inv-03). На дашборде (`dashboard_metrics`) показателей остатка нет.
