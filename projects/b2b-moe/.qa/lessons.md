## L-20261003-1 · Недостающие тестовые аккаунты
- Правило: для полного регресса нужны аккаунты נציג מכירות (с закреплённым buyer), עובד מחסן / מלקט, נהג и второй לקוח עסקי; пока их нет — тесты этих ролей пишутся с `test.skip('нужен аккаунт <роль>')`, проверка только под admin и buyer.
- Почему: «протесть тикеты аккаунтов которые у тебя есть».
- Пример: backfill 2026-10-03.
- Источник: сообщение пользователя, 2026-10-03

## L-20261004-1 · Раскладка RTL — по картинке Figma, не по словам AC
- Правило: находку «экран зеркален макету» заводить только после визуального сравнения со скриншотом фрейма Figma (какой блок слева/справа, порядок плиток). Слова AC «start/end», «справа/слева» не считать источником — при расхождении AC и картинки макет главнее, а расхождение показать пользователю. Карточка клиента (Figma 71:644): детали СЛЕВА, «הזמנות אחרונות» СПРАВА — так правильно.
- Почему: «вот так у нас должно быть. так будет правильнее по ртл» — наш тикет #ba86d972 (из AC #6a6755e0 «פרטים ב-start») требовал обратного макету, и программист увёл экран от Figma.
- Пример: b2b-moe #ba86d972, тест-кейс cp-06 п.4, 2026-10-04.
- Источник: сообщение пользователя, 2026-10-04
- Область: проект

## L-20261005-1 · Нет комментария программиста — проверять по самому тикету
- Правило: если тикет вернулся в «בבדיקות» без комментария программиста (в т.ч. после нашего реджекта), не считать это проблемой и не спрашивать — проверять поведение из тикета (מה קיים / מה רצוי / открытые реджекты) на сайте и по факту решать, есть ли исправление.
- Почему: «бывает что нету коментария от программиста. смотри тогда по самому тикету если есть фикс».
- Пример: b2b-moe 05.10 — 9 тикетов в בבדיקות переведены 04.10 21:35 без комментариев.
- Источник: сообщение пользователя, 2026-10-05
- Область: проект
- Статус: действует

## L-20261012-1 · Реджекты закрывать после «прошёл», с телефоном — после телефона
- Правило: после «прошёл» закрывать открытые реджекты тикета через MCP («סמן כטופל»), включая реджект на исходной задаче в «הושלם», если тикет — его исправление. Иначе Julius maintenance снова берёт открытый реджект в работу. Если у тикета отложена проверка на реальном телефоне — ничего на доске не делать, пока её нет.
- Почему: «тогда сделай» (после объяснения про открытый 30fbd2fc), «#7b8b97e9 — тогда оставь на потом когда будет телефон».
- Пример: b2b-moe 12.10 — 30fbd2fc на #6a8f3153 закрыт; закрытие реджекта #7b8b97e9 отменено до iPhone.
- Источник: сообщение пользователя, 2026-10-12
- Область: проект
- Статус: действует

## L-20261014-1 · Телефона нет — мобильное только эмуляцией
- Правило: реального телефона по кабелю для тестов нет. Всё мобильное (iPhone/Android, 390/411 и т.д.) проверять эмуляцией устройства в headless-браузере (qa-browser-cli, профили iPhone/Pixel), в фоне. Пункты «на реальном телефоне» не откладывать «до телефона» — проверять эмуляцией и честно писать в вердикте «эмуляция, не реальное устройство».
- Почему: «телефон проверяй с разширением телефона. телефона нету для тестов».
- Пример: b2b-moe 14.10 — #6cdf674f Р3 (Android 411), #157fed2c.
- Источник: сообщение пользователя, 2026-10-14
- Область: проект
- Статус: действует (заменяет «отложить до iPhone» в L-20261012-1 проекта)

## L-20261014-2 · Перепроверять независимо только проваленные пункты (теперь общее правило плагина 0.9.10)
- Правило: bug-verifier запускается только на пункты «не выполнено» и на находки, которые идут в реджект/баг. Пункты, прошедшие с первого полного прогона, повторно не перепроверять. Вердикт «прошёл» — когда каждый пункт карты проверен полностью (без «почти»), и все провалы подтверждены перепроверкой. Заменяет требование «каждый пункт перепроверен» из общих L-20261004-5 / L-20261013-1 / L-20261013-4 для этого проекта.
- Почему: «перепроверяй независимо только провальные пункты. нет смысла проверять еще раз то что уже прошло с первого раза. и тогда всё ровно будет вердикт только при 100%».
- Источник: сообщение пользователя, 2026-10-14
- Область: проект
- Статус: действует

## L-20261014-3 · Мобильное — одна эмуляция 390; регресс связанных — автотестами
- Правило: мобильную часть тикета проверять одной эмуляцией iPhone 390 (без отдельного Android 411), если тикет прямо не про Android. Регресс связанных/«уже сделанных» тикетов руками не делать — прогонять их автотесты (.qa/e2e) в конце пакета, до вердикта. — ИЗМЕНЕНО 2026-10-14 (плагин 0.9.10, решение пользователя): внутри /qa регресс и автотесты не запускать вообще, только /qa-regress.
- Почему: пользователь выбрал «2 и 3 делай» на вопрос, как ускорить проверку 3 тикетов (14.10).
- Источник: сообщение пользователя, 2026-10-14
- Область: проект
- Статус: действует

## L-20261018-1 · ליקוט: товар без места («ללא מיקום») — отметка «לוקט» без проверки остатка — норма
- Правило: в ליקוט товар без места на складе («ללא מיקום») может отмечаться «לוקט» (и через «ליקוט הכל»), даже если остаток 0 и нет חוסר — это не баг, не заводить и не реджектить. Проверка нехватки нужна только для товара на полке (там «לוקט» блокируется и нужен «חסר» — так и работает).
- Почему: «если у товара нету места אין לו מיקום то нечего страшного. он может быть без места товар» (про заведённый #38d742).
- Пример: b2b-moe 18.10 — тикет #38d742 заведён ошибочно, пользователь удаляет.
- Источник: сообщение пользователя, 2026-10-18
- Область: проект
- Статус: действует

## L-20261025-1 · Мелкие сценарии вне тикета (выбор стрелками и т.п.) — не раздувать
- Правило: если поведение не описано в тикете и это мелкий сценарий ввода (напр. выбор стрелкой в выпадающем списке при Enter), не выносить его вопросом, не перепроверять и не предлагать баг — тикет проходит по своей карте, сценарий максимум одной строкой в находках.
- Почему: «типо выбор стрелочко? не вижу смысла на этом зацикливатся» — #5711c3, Т4.
- Пример: b2b-moe #5711c3 (מכירה מיידית, Enter + ↓), 2026-10-25.
- Источник: сообщение пользователя, 2026-10-25
- Область: проект
- Статус: действует

## L-20261101-1 · «Заводи» — создавать баг сразу, текст не показывать
- Правило: когда пользователь сказал «заводи» про находку — после проверки дублей и подтверждения bug-verifier создавать тикет в «לביצוע» сразу, без показа черновика текста и без отдельного «да». В ответе — только номер/hash созданного тикета и одна строка, о чём он. Если перепроверка НЕ подтвердила — не создавать, сказать об этом.
- Почему: «создавай сразу не пиши мне текст бага».
- Пример: b2b-moe Н1 (карточка клиента 0/₪0.00 при ошибке orders), 2026-11-01.
