## L-20261025-5 · Две оси сверки: требования и Figma
- Правило: по каждому тикету проверять две вещи: (1) работает и соответствует тикету и «מפרט» (логика, тексты, поля); (2) внешний вид сделан как в Figma (поэлементно, тёмная тема). Расхождение по составу или порядку между Figma и тикетом — требование берётся из тикета, конфликт указывается в вердикте; визуальное отличие от Figma — реджект.
- Почему: «мне надо что бы ты смотрел что работает и все выглядит правильно по документации и требованиям и смотрел что дизайн сделан как в фигме».

## L-20261028-1 · «Пункт есть в меню» ≠ действие проверено; экран без Figma в чужом тикете — тоже ждём дизайна
- Правило: перед «прошёл» по каждому AC с действием («можно пожаловаться», «можно заблокировать») — действие выполнено до конца и результат виден (жалоба отправлена и есть в админке и т.п.). «Пункт в меню есть / открывает экран» = частично → не «прошёл». Если экран тикета ждёт дизайна в другом тикете — «לא ניתן לשחזר — ממתין לעיצוב», а не «прошёл».
- Почему: 28.10 #9ab97a показан как «прошёл», а AC 12 (жалоба) проверен только по наличию пункта; пользователь спросил «всё прошло?», затем решил: экран ждёт дизайна → לא ניתן לשחזר.
- Источник: сообщение пользователя, 2026-10-28 · Область: проект (повтор общих L-20261007-1, L-20261013-4) · Статус: действует

## L-20261029-1 · Меньше вопросов: если ответ выводится из правил — решать самому
- Правило: не спрашивать то, что решается существующими правилами: «требование есть и не выполнено → реджект», «состав — по тикету/требованиям, вид — по Figma», «нужна помощь программиста → реджект с просьбой», выбор тестовых данных/профиля — какой нужен для тестов. Спрашивать только реальные противоречия источников, на которые правила не отвечают. Вопросы-«client-decisions» программиста без подтверждения клиента = требование по тикету/Figma, не вопрос.
- Почему: 29.10 из 9 вопросов по регистрации пользователь ответил на все «по требованиям / по Figma / реджект / делай нужное для тестов» и сказал: «тут много вопросов которые ты мог и не спрашивать».

- Статус: действует

## L-20261029-3 · Push-уведомления в вебе не проверить → «לא ניתן לשחזר — נדרשת אפליקציה», не реджект
- Правило: пункт про push (доставка/заглушение на устройстве) — не причина реджекта. Если в тикете кроме push всё сделано → «לא ניתן לשחזר» с заметкой, что для push нужно приложение. Если есть и другие несделанные пункты → закрыть реджект с push, открыть новый реджект только с тем, что не так (без push), и поставить «לא ניתן לשחזר» (push ждёт приложения).
- Почему: 29.10 #8ad381 — я отправил реджект с просьбой о доказательстве push; пользователь: «если надо пуш уведомление то надо сделать לא ניתן לשיחזור что нужно приложение…».
- Источник: сообщение пользователя, 2026-10-29 · Область: проект · Статус: действует

## L-20261101-1 · Magnet: в Figma есть анимации — сверять и их
- Правило: кроме статичных кадров сверять анимации из Figma — переходы прототипа (тип, длительность, easing), smart animate, motion-компоненты (прелоадер, появление шитов, мэтч, лайк и т.п.). Источник — Figma MCP get_motion_context / get_design_context по узлу экрана; на сайте — замер через requestAnimationFrame/getAnimations() (длительность, задержки, траектория), покадровые скриншоты. Анимация есть в Figma и нет/другая на сайте → это расхождение с дизайном (реджект по L-20261025-5). Видео с анимациями вне Figma дизайнер пришлёт через пользователя — тоже источник дизайна для соответствующих экранов.
- Почему: «дизайнер сказал что в фигме ещё есть анимации. так что обращай внимание тоже на анимации которые есть в фигме».
- Источник: сообщение пользователя, 2026-11-01

- Статус: действует

## L-20261102-1 · Magnet: `locator.click()` прокручивает ленту на 31px
Документ ленты выше экрана на 31px. Если цель перекрыта прелоадером или ещё въезжает, Playwright `locator.click()` докручивает окно, и все y сдвигаются на 31. Проверено bug-verifier на #5ab721, 02.11. Для замеров вертикальных позиций кликать по координатам или ждать, пока `elementFromPoint` вернёт саму цель. «Шит на 31px выше» — артефакт инструмента, не баг.

## L-20261102-2 · Нет анимации, которая есть в прототипе Figma, — это реджект
Если в прототипе Figma на переходе стоит Smart Animate или другая анимация, а на сайте переход мгновенный, это реджект, а не заметка «к сведению». Пользователь, #24d071, 02.11: «реджект, должна быть анимация».

## L-20261102-3 · Программист не видит комментарии в mifrat — всё для него только реджектом
Всё, что адресовано программисту (уточнения, требования, ссылки на кадры), оформлять реджектом, а не комментарием. Уточнение к уже отправленному реджекту — закрыть старый (סמן כטופל) и открыть новый с полным текстом. Пользователь, 02.11: «программист коментарии не видит. если ты пишешь что то для программиста то делай реджект».

## L-20261104-3 · Просьбы программисту — только через реджект
- Правило: программист не читает комментарии и пометки «לא ניתן לשחזר». Если от программиста что-то нужно (данные, аккаунт, Premium, доступ), делай реджект с этой просьбой, а не «לא ניתן לשחזר» с заметкой. «לא ניתן לשחזר» — только когда ждём то, что программист сделать не может (оплата, приложение, номера уже в отдельном тикете).
