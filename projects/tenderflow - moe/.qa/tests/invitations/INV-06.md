# INV-06: Валидный token + подменённые email/name/company/inviter — экран и signUp с данными приглашения
- Фича/экран: invitations — /accept?token=…
- Тикеты: #83bf5b
- Роль/аккаунт: ADMIN2 (компания B) приглашает; гость без входа открывает ссылку
- Устройство: desktop 1440×900
- Тип: негатив (подмена параметров)
- Предусловия: свежее приглашение `qa-auto-inv-<run>@example.com` (`QA-AUTO Invite`). Регистрации нет: запрос `auth/v1/signup` в автотесте прерывается (route.abort) до сервера. В конце — отмена приглашения через окно «ביטול ההזמנה». `@data`.
- Автотест: `.qa/e2e/tests/invitations/accept-from-server.spec.ts` (два теста: экран; email в signUp)
## Шаги
1. ADMIN2 приглашает → ссылка L из баннера.
2. Гость открывает L — контроль: «שלום QA-AUTO Invite, הוזמנת לחשבון של», «QA Company B», строка «<пригласивший> צירף אותך», поле «אימייל ארגוני» (מההזמנה) = адрес приглашения.
3. Гость открывает L + `&email=qa-auto-inv-spoof-…@example.com&name=QA-AUTO+Spoof&company=QA-AUTO+Other+Co&inviter=QA-AUTO+Inviter`.
4. Ввести пароль, «קבע סיסמה והיכנס» — запрос signUp перехвачен и прерван; смотреть email в теле запроса.
5. Очистка.
## Ожидаемо
- Шаг 3: экран как на шаге 2 — имя, компания, строка пригласившего и email из приглашения; поле email только для чтения со значением приглашения; подменённые значения нигде не показаны; при открытии signUp нет (источник: «מה רצוי» — «הנתונים במסך … נלקחים מההזמנה בשרת לפי הטוקן בלבד. שינוי פרמטרים בקישור אינו משנה את מה שמוצג»).
- Шаг 4: один запрос signUp, `email` = адрес приглашения, не подменённый («מה רצוי»: «ובמיוחד אינו משנה את האימייל שאיתו נוצר החשבון»).
