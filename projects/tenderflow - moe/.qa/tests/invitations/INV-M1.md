- Тикеты: #83bf5b
- Роль/аккаунт: ADMIN2 (компания B) приглашает; гость без входа
- Устройство: desktop 1440×900
- Тип: негатив (безопасность)
- Предусловия: создаёт настоящий аккаунт → только по отдельному «да» пользователя, на одноразовом ящике; после — удалить auth-пользователя в Supabase (журнал test_data). Не автоматизируется: нужна настоящая регистрация.
## Шаги
1. Гость открывает действующую ссылку; в DevTools снять `readonly` у поля «אימייל ארגוני», ввести другой адрес.
2. Пароль → «קבע סיסמה והיכנס».
3. Смотреть сеть: `auth/v1/signup`, `rpc/accept_invitation`; затем /users у ADMIN2.

- Аккаунт с чужим адресом не попадает в компанию: `accept_invitation` → 403, приглашение остаётся «הזמנה ממתינה», в /users нового участника нет (источник: «מה רצוי» — аккаунт создаётся только с email приглашения; принято пользователем 15.11).
