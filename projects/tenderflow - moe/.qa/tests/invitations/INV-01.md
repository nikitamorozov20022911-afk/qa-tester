# INV-01: Отменённое приглашение — ссылка недействительна, формы пароля нет
- Фича/экран: invitations — /users («משתמשי החברה», «ביטול הזמנה»), /users/invite, /accept?token=…
- Тикеты: #af0ff2
- Роль/аккаунт: ADMIN2 (`ADMIN2_EMAIL`), מנהל חשבון компании B «QA Company B»; сессия `.qa/auth/admin2.json`. Ссылку открывает гость — чистый контекст без входа.
- Устройство: desktop 1440×900
- Тип: негатив (безопасность)
- Предусловия: в /users компании B только ADMIN2. Свежий адрес `qa-<run>@example.com` (не использовавшийся раньше).
- Автотест: `.qa/e2e/tests/invitations/cancelled-invite-link.spec.ts`
## Шаги
1. ADMIN2: /users → «הזמנת משתמש חדש» → «שם מלא», «אימייל» = `qa-<run>@example.com`, «סוג הרשאה» по умолчанию (משתמש רגיל) → «שמירה והזמנה».
2. На /users в зелёном баннере «המשתמש נוסף לרשימה כהזמנה ממתינה. שלחו לו את קישור ההצטרפות (מוצג פעם אחת):» скопировать ссылку `…/accept?token=…` (L1). В таблице строка с email и статусом «הזמנה ממתינה».
3. В строке приглашения нажать «ביטול הזמנה».
4. Гость (другой браузер/инкогнито, без входа) открывает L1. DevTools → Network.
5. Очистка: убедиться, что в /users нет приглашения; остаётся только ADMIN2.
## Ожидаемо
- Шаг 3: строка приглашения исчезает из списка (подтверждения нет — находка, не требование).
- Шаг 4: заголовок «ההזמנה אינה תקפה», текст «ההזמנה בוטלה או שאינה תקפה עוד. פנו למנהל החשבון.», кнопка «חזרה לכניסה»; полей «סיסמה חדשה» / «אימייל» и кнопки «קבע סיסמה והיכנס» нет (источник: «מה רצוי» #af0ff2 — «הקישור שנשלח הופך ללא תקף … ללא טופס קביעת סיסמה»; текст сообщения — «למשל»).
- Сеть: `rest/v1/rpc/invitation_is_valid` отвечает `false`; запроса `auth/v1/signup` нет (источник: «מה רצוי» — «אין יצירת משתמש, אין שליחת אימייל ואין צירוף לחברה»).
- Шаг 5: в /users только ADMIN2, пустое состояние «אין עדיין משתמשים נוספים בחברה».
