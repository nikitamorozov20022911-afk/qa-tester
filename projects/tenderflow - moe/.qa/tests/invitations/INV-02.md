# INV-02: Повторное приглашение того же email — старая ссылка недействительна, новая работает
- Фича/экран: invitations — /users/invite, /users, /accept?token=…
- Тикеты: #af0ff2
- Роль/аккаунт: ADMIN2 (`ADMIN2_EMAIL`), компания B; сессия `.qa/auth/admin2.json`. Ссылки открывает гость без входа.
- Устройство: desktop 1440×900
- Тип: негатив (безопасность) + позитивный контроль
- Предусловия: в /users компании B только ADMIN2. Свежий адрес `qa-<run>@example.com`.
- Автотест: `.qa/e2e/tests/invitations/cancelled-invite-link.spec.ts`
## Шаги
1. ADMIN2: пригласить `qa-<run>@example.com` (как INV-01, шаг 1) → ссылка из баннера L1.
2. Пригласить тот же email ещё раз (/users/invite, те же данные, «שמירה והזמנה») → ссылка из баннера L2 (L2 ≠ L1).
3. Гость открывает L1.
4. Гость открывает L2. **Форму не отправлять, пароль не вводить.**
5. Очистка: «ביטול הזמנה» у приглашения; в /users только ADMIN2.
## Ожидаемо
- Шаг 3: «ההזמנה אינה תקפה» + «ההזמנה בוטלה או שאינה תקפה עוד. פנו למנהל החשבון.», формы пароля нет (источник: «מה רצוי» — «אותו דבר עבור קישור ישן לאחר הזמנה מחדש לאותו אימייל»).
- Шаг 4: форма приглашения — «הוזמנת לחשבון של» «QA Company B», поле «אימייל» со значением приглашённого адреса только для чтения (пометка «מההזמנה»), поле «סיסמה חדשה», кнопка «קבע סיסמה והיכנס» (контроль: новая ссылка должна работать — смысл функции приглашения).
- Шаг 5: в /users только ADMIN2.
