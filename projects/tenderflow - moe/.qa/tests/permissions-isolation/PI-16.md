# PI-16: company_profiles на сервере — USER не может update / insert / upsert профиль своей компании
- Фича/экран: permissions-isolation — Supabase REST `company_profiles` (RLS profiles_insert / profiles_update = is_company_admin)
- Тикеты: #3f693e
- Роль/аккаунт: USER (`.qa/auth/user.json`, компания A); ADMIN (`.qa/auth/admin.json`) — только чтение строки до/после
- Устройство: desktop (API)
- Тип: негатив (права, сервер)
- Предусловия: у компании A есть строка профиля. Секреты не хранятся: apikey и токен — из запроса, который сайт сам шлёт при открытии «/».
- Автотест: `.qa/e2e/tests/permissions-isolation/member-company-profiles-rls.spec.ts` (@data)
## Шаги
1. ADMIN читает строку company_profiles своей компании (все поля, включая updated_at).
2. USER: PATCH company_profiles?company_id=eq.<A> с тем же company_id.
3. USER: POST company_profiles {company_id: A}.
4. USER: POST ?on_conflict=company_id, Prefer: resolution=merge-duplicates.
5. ADMIN снова читает строку.
## Ожидаемо
- PATCH: 200 и `[]` (0 строк). Insert и upsert: 403, код 42501 (AC #3f693e «insert or update … refused»).
- Строка до и после идентична (updated_at не изменился).
