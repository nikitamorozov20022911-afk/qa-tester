## R-05 שירה – מנהלת תפעול ותמיכה (Admin)

- **Тип:** персона, сотрудник — Admin
- **Источник:** מפרט → Personas, id `63b2390eaa28ea3f8441cb66`
- **Роль (role):** אשת צוות שמנהלת משתמשים, מנויים ו-Affiliates בממשק ה-Admin
- **Цели (jobs_to_be_done):**
  - לצפות ברשימת המשתמשים, בסטטוס החשבון והמנוי ולטפל בחשבון בעת הצורך
  - לנהל מנויים: סוג חבילה, סטטוס, תאריכי התחלה וחידוש וביצוע ביטול
  - ליצור Affiliates, להנפיק קודים ולעקוב אחר המשתמשים והמנויים שהגיעו דרך כל שותף
  - להפיק את הנתונים הדרושים לחישוב עמלה חוזרת לשותפים ומשפיענים
- **Боли (customer_pains):**
  - בירורי מנוי וביטולים דורשים הצלבה ידנית בין מערכת התשלומים לנתוני המשתמש
  - קושי לשייך משתמשים לשותף הנכון ולהוכיח את מקור ההגעה לצורך עמלה
  - חשיפה לא רצויה למידע אישי ורגיש של משתמשים בזמן טיפול תפעולי
- **Ожидаемая ценность (customer_gains):**
  - מסך אחד לכל סטטוס החשבון והמנוי של המשתמש עם פעולת טיפול ישירה
  - מעקב Affiliate מסודר לפי קוד ייחודי עם נתוני עמלה מרוכזים
  - API ניהול מוגבל לצוות בלבד שמחזיר נתוני ניהול בלי לחשוף מידע אישי מיותר
- **Права (из фич, дословно):**
  - «ניהול משתמשים בממשק Admin»: «מחייב הרשאת Admin לכל פעולה בניהול משתמשים»; «מכבד בקשת מחיקת חשבון של משתמש גם בתצוגת ה-Admin»; описание: «אינה כוללת גישה חופשית לתוכן השיחות האישיות של המשתמש».
  - «ניהול מנויים בממשק Admin»: «מחייב הרשאת Admin לכל פעולת ניהול מנוי».
  - «ניהול Affiliates ועמלות»: «מחייב הרשאת Admin לכל פעולת ניהול Affiliate»; «אינו כולל העברת כספים אוטומטית לשותפים בשלב הראשון».
  - «API מנויים ושיוך Affiliate»: «מחייב הרשאת Admin לצורך גישה לנתוני מנויים ו-Affiliates של משתמשים אחרים»; «מחייב הרשאת Admin לצורך אישור או דחייה של בקשת Affiliate».
  - «API ניהול מערכת»: «מחזיר שגיאה כאשר הבקשה מגיעה ממשתמש שאינו בעל הרשאת Admin».
  - «קונפיגורציית Safe Zone וגבולות BMI ב-Admin»: Admin задаёт диапазоны BMI, блок снижения веса при беременности, статусы цели (נתמכת / דורשת אזהרה / חסומה), текст объяснения; «שומר היסטוריית שינוי של כללי Safe Zone כולל זמן שינוי ומשתמש אדמין שביצע אותו»; «מונע ממסך הקונפיגורציה לחשוף פרטי בריאות של משתמשים ספציפיים».
- **Что видит / может (экраны из фич):**
  - «מסך ניהול משתמשים» — таблица (מזהה, סטטוס חשבון, סטטוס מנוי), поиск по имени/מזהה, карточка пользователя, «פעולת טיפול בחשבון» с подтверждением, переход в ניהול מנויים.
  - «מסך ניהול מנויים» — סוג חבילה, סטטוס, даты начала/חידוש, ביטול с окном подтверждения, фильтр по סוג חבילה и סטטוס.
  - «מסך ניהול Affiliates» — список, создание Affiliate с уникальным кодом, очередь заявок (фильтр по статусу), אישור / דחייה с סיבת דחייה, правка кода перед активацией, запрет утверждения при занятом коде, карточка Affiliate (пользователи, активные מנויים, данные для עמלה).
  - Safe Zone / BMI — конфигурация (экран отдельно не описан, только feature).
- **Не указано:** что именно входит в «פעולת טיפול בחשבון» (блокировка? приостановка?) — в документации не раскрыто.

## R-06 Affiliate / מועמד Affiliate (שותף, משפיען)

- **Тип:** внешняя роль (не персона — в списке Personas отсутствует), выведена из фич модуля «מנויים ו-Affiliate»
- **Источник:** מפרט → features «דף הרשמת Affiliate נפרד» (`7aead857c35461e07d47ec3b`), «מודל Affiliate ושיוך משתמשים» (`ab4d38afad976fe04406546f4c0ff2eb`), «API מנויים ושיוך Affiliate» (`1411f3af252b8c21aced0a338f0bb68f`)
- **Кто:** «שותף או משפיען» (описание дף הרשמה).
- **Цель (user_story):** «בתור Affiliate, אני רוצה קוד ייחודי שמשייך אליי את המשתמשים שגייסתי, כדי שאוכל לעקוב אחרי המנויים שהגיעו דרכי ולקבל עליהם עמלה.»
- **Что может:**
  - Подать заявку на отдельном публичном דף הרשמה «בלי להיכנס לממשק המשתמש הרגיל»: שם, אימייל, שם מותג או ערוץ, פרטי קשר, מקור קהל, קוד מועדף.
  - Заявка → статус «ממתינה לאישור»; «אינו יוצר קוד פעיל ואינו משייך משתמשים לפני אישור Admin».
  - Статусы заявки: ממתינה / מאושרת / נדחית; «חוסמת שיוך משתמשים לקוד Affiliate של בקשה ממתינה או נדחית».
- **Ограничения:** «אינה חושפת מידע אישי של המשתמש ל-Affiliate מעבר לנתונים הנדרשים למעקב»; «אינה מחייבת מנגנון אוטומטי להעברת כספים בשלב הראשון».
- **Не указано:** есть ли у Affiliate свой кабинет/вход для отслеживания пользователей — в документации нет (просмотр данных по Affiliate описан только в Admin).

## R-07 Конечный пользователь — подписка и тарифы (מנוי)

- **Тип:** общие права для R-01, R-02, R-03 (тарифная модель)
- **Источник:** מפרט → «מנוי ותשלומים» (`1465899e2f7792f7dbc5e264fa207154`), «מסך בחירת מנוי ותשלום» (`30c69c559f8adaecc8495ae28f47c442`), «אינטגרציית תשלומים ומנויים» (`089ae5a60cb4ec6bf05afda6656ac01a`)
- **Тарифы:** «מנוי חודשי», «חבילה של שלושה חודשים במחיר חודשי מופחת», «מנוי שנתי». Дословно: «המחירים ומבנה החבילות אינם סופיים וייסגרו בהמשך בהתאם לאסטרטגיה המסחרית.»
- **Цель (user_story):** «בתור משתמש קצה, אני רוצה לבחור חבילת מנוי ולשלם עליה, כדי לקבל גישה לליווי של ה-Wingman.»
- **Что может:** выбрать одну חבילה, ввести קוד Affiliate до завершения покупки, оплатить, увидеть подтверждение (סוג חבילה + תאריך חידוש), при ошибке — повторить; с активной подпиской — видеть статус/тип/дату חידוש и отменить подписку из экрана; ссылки на Terms of Use и Privacy Policy до покупки.
- **Правила:** «מעדכנת את סטטוס החשבון בהתאם לסטטוס המנוי»; автопродление в конце периода; при отклонённой транзакции — ошибка и статус מנוי не меняется; без двойной записи одной транзакции.
- **Не указано:** есть ли бесплатный/пробный период, что доступно без активной подписки и что происходит с доступом после отмены/неуспешного списания — в документации не найдено. Провайдер оплаты не выбран («תלויים בבדיקת היתכנות טכנית ובדרישות ה-App Stores»).

## R-08 Конечный пользователь — права на свои данные (פרטיות)

- **Тип:** общие права для R-01, R-02, R-03
- **Источник:** מפרט → «מחיקת מידע ומחיקת חשבון» (`e9c21dc57f5198041160499fd04b66ca`), модуль «פרטיות ושליטה במידע»; связан с «מסך הגדרות פרטיות ומחיקת מידע» (`33118cce447570226ab1134ef622a577`)
- **Цель (user_story):** «בתור משתמש קצה, אני רוצה למחוק את החשבון שלי או פריטי מידע מסוימים שנשמרו עליי, כדי לשמור על שליטה במידע האישי שלי.»
- **Что может (demands):**
  - מאפשרת למשתמש למחוק את חשבונו
  - מחיקה נקודתית: ארוחה, תמונה, נתון מיקום, מקום בזיכרון האישי, פריט מידע בזיכרון, פרטי שיחה, העדפת תקשורת שנלמדה
  - מאפשרת למשתמש לתקן מידע אישי שנשמר עליו במקום למחוק אותו
  - מפרידה בין מחיקת ההקשר האישי לבין שמירת מידע תזונתי אנונימי שאינו מאפשר לזהות את המשתמש
  - מעדכנת את המאזן היומי וההיסטוריה בהתאם לפריטים שנמחקו
- **Связь с Admin:** «מכבד בקשת מחיקת חשבון של משתמש גם בתצוגת ה-Admin» (R-05).
- **Отправка Feedback:** пользователь может сообщить о неверной информации / ошибочном распознавании / проблемном ответе / неуместном поведении ментора («דיווח משוב על תגובה או התנהגות»); отчёт уходит в Admin (R-04), «אינו משנה את התנהגות ה-Wingman באופן אוטומטי על בסיס דיווח בודד».
