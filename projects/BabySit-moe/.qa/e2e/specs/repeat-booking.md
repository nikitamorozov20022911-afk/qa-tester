# Repeat booking — הזמנה חוזרת (Repeat booking)

План автотестов для официального `playwright-test-generator`. Источник: тикет #8e159f (фича F-27 «הזמנה חוזרת», экраны S-16 בייביסיטרים קודמות → S-12 יצירת בקשה → S-13 מצב הבקשה → S-14 פרטי הזמנה, флоу FL-05, AC=3 demands, решение D-31) и бриф `.qa/research/8e159f.md`.
Сайт: https://babysit-qa.expo.app · he-IL (RTL), мобильный вид. Сессии ролей — `.qa/auth/<role>.json`.
Роли: **parent-verified** = dana@ (родитель, у которого есть завершённая Booking с maya — предусловие past-sitter/«מועדפת»), **sitter-experienced** = maya@ (бейбиситтер, принимает/отклоняет).
Макета нет (design_status none) — визуальная сверка не входит, проверяем поведение.

**Разметка мутаций.** Навигация и рейлы (past-sitters / favourites / переход «הזמן שוב») ничего не создают → `@prod-safe`. Создание повторного Request и accept/decline **создают/меняют бронь** → `@mutating`.
**Ограничение данных.** Два повторных Request из прошлой сессии израсходованы: `fcd590a0` (отклонён) и `efad10bc` (принят → активная бронь 16.11, 8 детей, 240₪) — см. `.qa/session.json`. Для `@mutating`-тестов нужен свежий повторный Request каждый прогон (создаёт сам тест). Создаваемые данные помечать префиксом **`QA-AUTO-`** где есть текстовое поле; шаг очистки/отмены — в конце теста (бронь после accept необратима через UI — фиксировать как тестовые данные).
**Решение to confirm (коммент).** Повторный Request **эксклюзивен** для preferred-бейбиситтер и **обходит матчинг**: нет «הבעת עניין», только accept/decline. Это ключевая проверка.
Мультиролевые тесты (parent + sitter одновременно) пишет сам `autotest-writer` через `asUser`, поле **Users** = несколько ролей.

#### 1.3 Родитель: «הזמן שוב» → `/requests/new?sitterId=…` с текстом эксклюзивности (#8e159f) `@prod-safe`
**Device:** all (без пометки)
**Users:** parent-verified
**Seed:** `tests/seed.parent-verified.spec.ts`
**Steps:**
1. Под сессией dana открыть `/past-sitters` (или рейл на `/home`), на карточке maya нажать «הזמנה נוספת / הזמן שוב».
2. Дождаться перехода на экран нового Request.
3. Прочитать заголовок/подпись экрана (БЕЗ отправки Request).
**Expected:**
- Переход открывает новый Request с привязкой к бейбиситтер: URL вида `/requests/new?sitterId=<maya>` (`waitForURL(/\/requests\/new\?.*sitterId=/)`). (источник: Т3/AC2/AC3; FL-05 шаг 2.)
- Бейбиситтер на экране помечена «מועדפת» (favourite/preferred). (источник: Т3/AC3; FL-05 — «הבייביסיטר מסומנת כמועדפת».)
- Присутствует текст эксклюзивности — что запрос идёт напрямую этой preferred-бейбиситтер (а не в общий матчинг). (источник: коммент — повторный Request эксклюзивен preferred-бейбиситтер, обходит матчинг.)
- Request НЕ отправляется в этом тесте (только навигация и чтение) → `@prod-safe`. (источник: правило — отправка = `@mutating`.)

#### 1.4 Бейбиситтер `/jobs`: секция «הזמנות חוזרות» с accept/decline, без «הבעת עניין» (#8e159f) `@prod-safe`
**Device:** all (без пометки)
**Users:** sitter-experienced
**Seed:** `tests/seed.sitter-experienced.spec.ts`
**Ограничение:** секция наполнена только при наличии ОЖИДАЮЩЕГО повторного Request к maya. Прежние Request израсходованы — для стабильного прогона нужен pending-Request seed (или запускать в связке после шага создания из 1.5). Если pending нет — проверять наличие самой секции/её пустого состояния.
**Steps:**
1. Под сессией maya открыть `/jobs` (входящие задания бейбиситтер).
2. Найти секцию «הזמנות חוזרות» (повторные приглашения).
3. Прочитать элементы управления в карточке повторного приглашения.
**Expected:**
- Присутствует отдельная секция «הזמנות חוזרות» для повторных приглашений. (источник: Т5; коммент — повторный Request приходит как accept/decline-приглашение.)
- В карточке повторного приглашения есть кнопки **accept** (אישור/קבל) и **decline** (דחייה/דחה). (источник: Т4/AC2/AC3; FL-05 шаги 4–5.)
- Кнопки/флоу «הבעת עניין» на повторном приглашении НЕТ (матчинг обойдён). (источник: Т5 — коммент: на повторном Request нет «הבעת עניין», только accept/decline.)

#### 1.5 Полный цикл: родитель создаёт повторный Request → бейбиситтер accept → новая Booking (#8e159f) `@mutating`
**Device:** all (без пометки)
**Users:** несколько ролей — parent-verified (dana), sitter-experienced (maya) — через `asUser`
**Seed:** `tests/seed.parent-verified.spec.ts` + `tests/seed.sitter-experienced.spec.ts`
**Ограничение/данные:** создаёт новый повторный Request и приводит к НОВОЙ confirmed Booking (необратимо через UI) — зафиксировать как тестовые данные, текстовые поля с префиксом `QA-AUTO-`. Пишет `autotest-writer` сам (две роли, два окна).
**Steps:**
1. `const parent = await asUser('parent-verified')`; `const sitter = await asUser('sitter-experienced')`.
2. parent: с карточки maya нажать «הזמן שוב», задать дату/часы, отправить Request (бейбиситтер «מועדפת»).
3. sitter: открыть `/jobs` → секция «הזמנות חוזרות», дождаться появления нового приглашения (ожидание через `expect`, без пауз), нажать accept.
4. parent: дождаться, что состояние Request перешло в подтверждённую Booking.
**Expected:**
- До accept бейбиситтер автоматической брони НЕ создаётся: пока бейбиситтер не приняла, Booking отсутствует. (источник: Т1/AC1/AC3 — «אין יצירה אוטומטית»; D-31.)
- После accept создаётся новая confirmed Booking (server-priced), видна у родителя (S-14 פרטי הזמנה). (источник: Т4/AC2/AC3; FL-05 outcome_success.)
- Действие бейбиситтер (accept) отражается в окне родителя — ожидание через `expect(...)`, не `waitForTimeout`. (источник: взаимодействие ролей, FL-05.)

#### 1.6 Ветка decline: бейбиситтер отклоняет → Request закрыт, родитель видит «נדחתה», не переоткрывается (#8e159f) `@mutating`
**Device:** all (без пометки)
**Users:** несколько ролей — parent-verified (dana), sitter-experienced (maya) — через `asUser`
**Seed:** `tests/seed.parent-verified.spec.ts` + `tests/seed.sitter-experienced.spec.ts`
**Ограничение/данные:** создаёт новый повторный Request (отклоняется) — текстовые поля `QA-AUTO-`, зафиксировать как тестовые данные. Пишет `autotest-writer` сам.
**Steps:**
1. `const parent = await asUser('parent-verified')`; `const sitter = await asUser('sitter-experienced')`.
2. parent: создать новый повторный Request к maya («הזמן שוב» → дата/часы → отправить).
3. sitter: в `/jobs` → «הזמנות חוזרות» нажать decline на этом приглашении.
4. parent: дождаться обновления состояния Request.
**Expected:**
- После decline Request закрыт, родитель видит статус отклонения «נדחתה»/«נסגרה». (источник: Т4/AC2; FL-05 outcome_failure — «הבייביסיטר דחתה את ההזמנה».)
- Повторный Request после отклонения НЕ переоткрывается сам — новый нужно создавать заново (кнопка «הזמן שוב» доступна для нового запроса, прежний не возвращается в pending). (источник: коммент — повторный Request не переоткрывается после отмены/отказа бейбиситтер.)
- Никакой Booking по отклонённому Request не создано. (источник: Т1/AC3 — «אין יצירה אוטומטית».)
