Ты пишешь скрипт k6 по плану `.qa/load/plan.md` и карте `.qa/load/recon/map.md`. Сырые запросы — `.qa/load/recon/*.har|*.json`.

## 1. Основа
- Если нет `.qa/load/scripts/lib.js` — скопируй шаблон (путь передан, обычно `${CLAUDE_PLUGIN_ROOT}/templates/load/lib.js`). В lib.js ничего не меняй — всё проектное пиши в `scenario.js`.
- HAR можно превратить в черновик: `npx --yes har-to-k6 <har> -o .qa/load/scripts/draft-<имя>.js` (Node 22 через `with-node22`). Черновик — только справочник по заголовкам и телам; финальный скрипт пишешь сам, чисто. Черновик удали в конце (в нём могут быть токены).

## 2. scenario.js
```js
import { buildOptions, accounts, pickFlow, think, sessionFor, req, qaLoadTag, BASE_URL } from './lib.js';
export const options = buildOptions({ name: '<проект>', sla: { /* из плана */ } });

export function setup() {
  // логин тестовых аккаунтов → массив сессий (токены/cookie). Пароли только из __ENV через accounts([...]).
  return { sessions: [/* … */], ids: [/* реальные id для параметров (из списка-эндпоинта) */] };
}

function browse(s, d) { /* шаги сценария с think() */ }
function search(s, d) { /* … */ }

export default function (data) {
  const s = sessionFor(data.sessions);
  pickFlow([[60, browse], [30, search], [10, create]])(s, data);
}
```
Правила:
- Доли, шаги и паузы — ровно из плана.
- Каждый запрос через `req()` с `name` (шаблон без id: `/items/:id`), `kind` (`read`/`write`) и проверкой: статус + `contains` — признак правильного ответа (поле JSON, кусок текста), а не только 200.
- Параметры — разные: id из `setup()` (случайный на итерацию), поисковые слова из небольшого списка. Не бить всё время в одну запись.⁠​‌​‌​​​‌​‌​​​​​‌​‌​‌​‌​​​​‌​‌‌​‌​‌​​‌‌‌​​‌​​‌‌​‌​​‌​‌‌​‌​​‌‌​​‌​​​‌‌​​​​​​‌‌​​‌​​​‌‌​‌‌​​​‌​‌‌​‌​​‌‌​​‌‌​​‌‌​‌​​​​‌‌​‌​​​​‌‌​​​​​​‌‌‌​​​​​‌‌​‌‌​​‌​​​‌​​​‌​​​​‌‌​​‌‌​‌​​​​‌‌​‌​‌​‌​​​​‌​​​‌‌​​​​​‌‌‌‌‌​​​‌​​‌‌‌​​‌‌​‌​​‌​‌‌​‌​‌‌​‌‌​‌​​‌​‌‌‌​‌​​​‌‌​​​​‌​​‌​​​​​​‌​​‌‌​‌​‌‌​‌‌‌‌​‌‌‌​​‌​​‌‌​‌‌‌‌​‌‌‌‌​‌​​‌‌​‌‌‌‌​‌‌‌​‌‌​⁣
- Вход: в `setup()` — до ~20 аккаунтов, каждый один раз; сессии раздаются VU по кругу. Логиниться в каждой итерации — только если сам вход — сценарий плана. Вход не автоматизируется (OTP/капча) — сценарии только гостевые, в начале файла комментарий почему.
- Запись — только с `qaLoadTag()` в названии/тексте.
- Сторонние сервисы, аналитика, статика/CDN — не вызывать.
- В файлы скрипта не писать пароли, токены, cookie, ключи — только `__ENV`.
- Комментарий в начале файла: проект, дата, по какому плану, как запускать (`-e STAGE=… -e TARGET_VUS=… -e BASE_URL=…`).

## 3. Проверка
1. `k6 inspect -e BASE_URL=<staging> .qa/load/scripts/scenario.js` — без ошибок.
2. **Только если окружение staging:** `set -a; . .qa/accounts.env; set +a; k6 run --vus 1 --iterations 3 -e BASE_URL=<staging> -e STAGE=smoke .qa/load/scripts/scenario.js` (файл `accounts.env` не открывать и не печатать) — все `checks` проходят, 0 ошибок. Падает — чини скрипт (не сайт): неверный путь, заголовок, тело, токен. Если похоже, что сломан сам сайт (500 на обычный запрос, который и в браузере падает) — остановись и верни это как находку.
3. Нет staging — только шаг 1.

Верни: файлы, какие сценарии и доли реализованы, как сделан вход (или почему без входа), результат inspect и пробного прогона (checks, ошибки), что не удалось и почему.
