# qa-tester

QA-тестировщик для Claude Code: проверяет тикеты из колонки «בבדיקות» в mifrat, выносит вердикт, пишет реджекты и баги, делает ежедневную сводку, хранит тест-кейсы и превращает их в автотесты Playwright.

## Установка

Распакуй архив `qa-tester-kit` в постоянное место (например, `~/qa-tester-kit`) и запусти один раз:
```bash
bash ~/qa-tester-kit/install.sh
```
Плагин ставится один раз на компьютер и дальше работает в любой папке проекта.
Нужен **Node.js 20 или новее** (для Playwright MCP и автотестов). Проверка: `node -v`.

## Начало работы в проекте

1. Открой Claude Code в папке тестируемого проекта.
2. `/qa-onboard` — ссылки, языки, документация → `.qa/` (контекст, база знаний, каркас автотестов).
3. Один раз войди в mifrat в окне браузера плагина (профиль сохранится).
4. Если нужны аккаунты: заполни `.qa/accounts.env`, запусти `npm run qa-login` (см. `.qa/e2e/README.md`).
5. Вход по SMS / Google / 2FA — `npm run qa-login:manual -- <аккаунт>` (окно браузера, входишь сам).
6. `/qa` — сессия тестирования.

| Команда | Что делает |
|---|---|
| `/qa` | Сессия: очередь «בבדיקות» → анализ → тест → вердикт → действие на доске (с подтверждением) |
| `/qa продолжаем` или «продолжаем» | Продолжить с handoff |
| `/qa #hash` | Проверить один тикет |
| (новый чат, любое сообщение) | **Меню с кнопками**: продолжить с прошлого места / тикеты / регресс / другое. Прогресс сохраняется автоматически после каждого тикета/шага |
| `/qa-handoff` или «сделай хендофф» | Сохранить состояние для новой сессии |
| `/qa-onboard` | Подготовить новый проект |
| `/qa-regress` | Регресс: прогнать записанные автотесты принятых тикетов и разобрать падения (только по команде) |
| поправка в чате («не так…», «запомни…») | Агент сам записывает урок: проект → `.qa/lessons.md`, общий → `~/.qa-tester/lessons.md` |
| `/qa-full [раздел]` | Полная проверка сайта (новый проект): все сценарии, негатив, UX, десктоп + iPhone + Android. Сначала план → «да» |
| `/qa-negative [раздел] [устройство]` | Только негативные и граничные тесты |
| `/qa-ux [раздел]` | Только UX на десктопе |
| `/qa-android [раздел \| #hash]` | Только Android: раздел или конкретный тикет |
| `/qa-iphone [раздел \| #hash]` | Только iPhone: раздел или конкретный тикет |
| `/qa-backfill [следующие 150]` | Записать в регресс уже принятые тикеты из «הושלם»: последние 150, затем следующие 150 и т.д. (без запуска). Первые 150 записываются автоматически в конце `/qa-onboard` |
| `/qa-client [просьбы клиента]` | Просьбы клиента → тикеты «בקשת לקוח: …» в «לביצוע» (после «да») + запомнить в реестре; сравнение с документацией только у нас, документацию не меняет |
| `/qa-improve` | Перенести накопленные уроки в сам плагин (только автор, с подтверждением каждой правки) |

## Что внутри

- **Скиллы:** `qa-session` (оркестратор), `qa-ticket-analysis`, `qa-test-design`, `qa-evidence`, `qa-verdict`, `mifrat-board`, `qa-testcases`, `qa-report`, `qa-context`, `qa-handoff`, `qa-onboard`.
- **Агенты:** `ticket-researcher`, `qa-tester`, `bug-verifier`, `onboard-extractor`, `onboard-consolidator`, `onboard-verifier`, `autotest-writer`, `regression-triager`.
- **Официальные агенты Playwright** (ставятся в проект при `/qa-onboard`): planner, generator — пишет автотесты, проверяя шаги в живом браузере; healer — чинит тесты только после диагностики «ошибка теста».
- **MCP:** Playwright (отдельный браузер с профилем `.qa/browser-profile`, скриншоты в `.qa/screenshots`).
- **Хук:** при старте сессии напоминает о незаконченном handoff.

## Принципы

- Вердикт по «מה קיים» и требованиям тикета + документации; строго в объёме тикета.
- Всё, что пишет на доску, — после подтверждения.
- Пароли не вводятся агентом; аккаунты не создаются; оплата не завершается.
- Перед действием на доске проверяется `#hash` открытой карточки; клики по доске — только JS.
