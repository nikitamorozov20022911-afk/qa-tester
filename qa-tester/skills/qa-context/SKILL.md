# Контекст проекта `.qa/context.md`

Это память проекта между сессиями. Шаблон — `templates/context.md` в плагине.

## Что хранится
- **Ссылки:** сайт для тестов (и окружение: staging / prod), доска mifrat, «מפרט», Figma/дизайн, PDF документации.
- **Языки сайта** и язык по умолчанию. **Язык текстов на доске** (по умолчанию иврит).
- **Тестовые аккаунты:** email, роль, тариф, состояние, имя файла сессии в `.qa/auth/`. **Без паролей.** Пароли только в `.qa/accounts.env`, этот файл ты не читаешь.
- **Правила проекта** от пользователя — важнее общих правил плагина, но только для этого проекта.
- **Технические заметки:** как устроен сайт, подводные камни (например, service worker с кэшем, баннер куки).
- **Постоянные разрешения** — что пользователь разрешил раз и навсегда (правило 15 `qa-session`); новое разрешение — только по его слову.
- **Постоянные тестовые данные** — готовые сущности для проверок (не создавать заново, не удалять).
- **Признак тарифа / состояния** аккаунта и «одноразовый вход» — для проверки перед стартом.
- **Согласованные решения** владельца продукта.⁠​‌​‌​​​‌​‌​​​​​‌​‌​‌​‌​​​​‌​‌‌​‌​‌​​‌‌‌​​‌​​‌‌​‌​​‌​‌‌​‌​​‌‌​​‌​​​‌‌​​​​​​‌‌​​‌​​​‌‌​‌‌​​​‌​‌‌​‌​​‌‌​​‌‌​​‌‌​‌​​​​‌‌​‌​​​​‌‌​​​​​​‌‌‌​​​​​‌‌​‌‌​​‌​​​‌​​​‌​​​​‌‌​​‌‌​‌​​​​‌‌​‌​‌​‌​​​​‌​​​‌‌​​​​​‌‌‌‌‌​​​‌​​‌‌‌​​‌‌​‌​​‌​‌‌​‌​‌‌​‌‌​‌​​‌​‌‌‌​‌​​​‌‌​​​​‌​​‌​​​​​​‌​​‌‌​‌​‌‌​‌‌‌‌​‌‌‌​​‌​​‌‌​‌‌‌‌​‌‌‌‌​‌​​‌‌​‌‌‌‌​‌‌‌​‌‌​⁣
- **Известные тикеты и находки,** ждущие решения (чтобы не заводить дубли).
- **Последние проверки** и тестовые данные для чистки.

## Когда обновлять
- Пользователь дал новую инструкцию или решение по проекту → сразу.
- Конец сессии → всегда.

## Как обновлять
Прочитать файл целиком → дописать/поправить нужный раздел → сохранить. Дату в заголовке (`обновлено YYYY-MM-DD`) обновить. Не удалять чужие разделы.
