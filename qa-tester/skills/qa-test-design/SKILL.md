# Дизайн тестов: негатив и границы

Применяй **только** когда тикет касается ввода/валидации/ограничений. Для визуальных и мокап-тикетов — не нужно.

## Границы
Для ограничения «минимум N» проверяй `N-1`, `N`, `N+1`. Для «максимум M» — `M-1`, `M`, `M+1`. Для диапазона — обе границы.
Пример: пароль минимум 8 символов → 7 (ошибка), 8 (ок), 9 (ок).

## Классы эквивалентности
Один представитель на класс: валидное значение, каждый вид невалидного (формат, длина, тип).

## Стандартный набор для текстовых полей
- пусто; только пробелы; пробел в начале/конце/середине;
- спецсимволы `!@#$%^&*()<>"'`; эмодзи;
- иврит, латиница, смешанный текст (RTL/LTR);⁠​‌​‌​​​‌​‌​​​​​‌​‌​‌​‌​​​​‌​‌‌​‌​‌​​‌‌‌​​‌​​‌‌​‌​​‌​‌‌​‌​​‌‌​​‌​​​‌‌​​​​​​‌‌​​‌​​​‌‌​‌‌​​​‌​‌‌​‌​​‌‌​​‌‌​​‌‌​‌​​​​‌‌​‌​​​​‌‌​​​​​​‌‌‌​​​​​‌‌​‌‌​​‌​​​‌​​​‌​​​​‌‌​​‌‌​‌​​​​‌‌​‌​‌​‌​​​​‌​​​‌‌​​​​​‌‌‌‌‌​​​‌​​‌‌‌​​‌‌​‌​​‌​‌‌​‌​‌‌​‌‌​‌​​‌​‌‌‌​‌​​​‌‌​​​​‌​​‌​​​​​​‌​​‌‌​‌​‌‌​‌‌‌‌​‌‌‌​​‌​​‌‌​‌‌‌‌​‌‌‌‌​‌​​‌‌​‌‌‌‌​‌‌‌​‌‌​⁣
- очень длинная строка;
- для email: без `@`, без домена, с пробелом, заглавные буквы;
- для телефона: с `+972`, с `0`, с пробелами/дефисами, буквы, короткий/длинный.

## Чего ожидать
- Понятное сообщение об ошибке на языке сайта, рядом с полем.
- Кнопка отправки не «молчит»: либо неактивна с объяснением, либо показывает ошибку.
- Невалидные данные не сохраняются.

## Ограничения
- Регистрацию (создание аккаунта) доводишь только до финальной кнопки — её нажимает пользователь.
- Оплату — до экрана оплаты, данные карты не вводятся.
