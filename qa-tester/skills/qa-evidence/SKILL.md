# Доказательства и окружение

## Свежая версия сайта (перед тестом)

Сайт может отдать старую версию из кэша service worker — тогда тестируется не то.
Проверь через JS:
```js
const reg = await navigator.serviceWorker?.getRegistration();
const nav = performance.getEntriesByType('navigation')[0];
({ waiting: !!reg?.waiting, fromSW: nav.workerStart > 0, transfer: nav.transferSize,
   banner: /גרסה חדשה|new version/i.test(document.body.innerText) })
```
- `waiting: true` или баннер «גרסה חדשה» → это старая версия. Нажми «רענון» / обнови, проверь снова.
- Для сценария «новый пользователь» очисти SW и кэш:
```js
for (const r of await navigator.serviceWorker.getRegistrations()) await r.unregister();
for (const k of await caches.keys()) await caches.delete(k);
```
- Если старая версия видна «вернувшемуся» пользователю — это **находка** (вне тикета), сообщи пользователю.

## Размер экрана
Используй устройство из сценария тикета. По умолчанию: iPhone 375×812, Android 412×915 (Pixel 7), десктоп 1440×900. Тикет про конкретную платформу (iPhone / Android) — проверяй на ней; «мобильный» без уточнения — на обоих телефонах. После теста верни размер обратно.

## Скриншоты
- Обязательны на каждый баг и на ключевые проверки. Без скриншота реджект не отправляется.⁠​‌​‌​​​‌​‌​​​​​‌​‌​‌​‌​​​​‌​‌‌​‌​‌​​‌‌‌​​‌​​‌‌​‌​​‌​‌‌​‌​​‌‌​​‌​​​‌‌​​​​​​‌‌​​‌​​​‌‌​‌‌​​​‌​‌‌​‌​​‌‌​​‌‌​​‌‌​‌​​​​‌‌​‌​​​​‌‌​​​​​​‌‌‌​​​​​‌‌​‌‌​​‌​​​‌​​​‌​​​​‌‌​​‌‌​‌​​​​‌‌​‌​‌​‌​​​​‌​​​‌‌​​​​​‌‌‌‌‌​​​‌​​‌‌‌​​‌‌​‌​​‌​‌‌​‌​‌‌​‌‌​‌​​‌​‌‌‌​‌​​​‌‌​​​​‌​​‌​​​​​​‌​​‌‌​‌​‌‌​‌‌‌‌​‌‌‌​​‌​​‌‌​‌‌‌‌​‌‌‌‌​‌​​‌‌​‌‌‌‌​‌‌‌​‌‌​⁣
- Сохраняются в `.qa/screenshots/` с именем `<hash>-<что>-<mobile|desktop>.png`, например `6eebcd2e-price-block-mobile.png`.
- **Красная обводка проблемы** перед скриншотом:
```js
const el = /* найденный проблемный элемент */;
el.scrollIntoView({block:'center'});
el.style.outline = '3px solid red'; el.style.outlineOffset = '2px';
```
После скриншота сними обводку (`el.style.outline = ''`).
- Числа (позиции, размеры) снимай через `getBoundingClientRect()` — так вердикт опирается на измерения, а не «на глаз».

## Визуальная сверка и расхождение с дизайном (любой тикет)
Сравни с Figma (Figma MCP) или с макетом из тикета: расположение, тексты, цвета, отступы, RTL, состояния (пусто/ошибка/загрузка). Разные реальные данные (имена, числа, количество строк) — не расхождение; сравнивается вёрстка, стиль и постоянные тексты.

**Экран не похож на дизайн → всегда «как в Figma» + «как у нас», никогда только фото сайта.**
1. **Кадр Figma** (по порядку): ссылка с `node-id` в тикете/комментариях/вложениях → ссылка на экран в «מפרט» (бриф `ticket-researcher`) → файл Figma из `.qa/context.md` + `get_metadata`, кадр с явно совпадающим названием экрана. Не уверен, что кадр тот, → спроси у пользователя ссылку на кадр (в сообщении с чек-листом), **не прикладывай угаданный кадр**. Макет-картинка, приложенная к тикету как «как надо», тоже годится.
2. **Снимок Figma — чёткий, не мелкий.** У `get_screenshot` параметр `maxDimension` ограничивает **длинную** сторону: длинный экран 1440×5000 при `maxDimension: 2048` выходит шириной ~590px — текст не читается (так ушли 5 плохих реджектов).
   - Расхождение в части экрана (блок, карточка, форма, кнопка) → снимай **узел этого блока**, не весь кадр: `get_metadata` по кадру → найди дочерний узел по названию/позиции → его `nodeId`.
   - `maxDimension` = длинная сторона узла × 2 (из `get_metadata` или `original_width/original_height` в ответе), максимум 8192. После ответа проверь: `width` ≥ `original_width` (масштаб не меньше 1×); меньше → повтори с большим `maxDimension` или возьми узел помельче.
   - Скачай по выданной ссылке: `curl -o .qa/screenshots/<hash>-<что>-figma.png "<url>"`.
3. **Снимок сайта — тот же экран и то же состояние:** ширина по кадру (≈375 → iPhone, ≈412 → Android, ≥1280 → десктоп 1440×900), та же вкладка/состояние; **та же область, что и снимок Figma**: узел-блок → скриншот этого же элемента (`locator.screenshot`), весь кадр → вся страница. Отличия обведи красным. Файл `<hash>-<что>-<desktop|iphone|android>.png`.
4. **Склейка** для программиста (из папки `.qa/e2e`; нет `compare.mjs` или в нём нет `--force` (старая версия) → скопируй из `templates/e2e/` плагина):
   `node compare.mjs ../screenshots/<hash>-<что>-figma.png ../screenshots/<hash>-<что>-<устройство>.png ../screenshots/<hash>-<что>-compare.png "<подпись Figma>" "<подпись сайта>" [--rtl]`
   **Подпись над каждым экраном обязательна** — сразу видно, где Figma, а где сайт/приложение. Без своих подписей скрипт ставит «Figma (עיצוב) — כך צריך להיות» и «באתר (בפועל) — כך זה עכשיו»; снимок из приложения → добавь `--app` («באפליקציה (בפועל)»). Доска на иврите → `--rtl`. Свои подписи — только на языке доски и с тем же смыслом.
   **Красная обводка на обеих половинах.** На сайте — обводка элемента до скриншота (как выше). В Figma — `--mark-figma x,y,w,h` (пиксели снимка Figma: позиция узла из `get_metadata` относительно снимаемого узла × масштаб снимка `width/original_width`); если на сайте обвести заранее не вышло — `--mark-site x,y,w,h` (из `getBoundingClientRect` × devicePixelRatio). Рамок можно несколько, по одной на каждое отличие.
   Скрипт сам не сжимает картинки и **отказывается** (код 2), если снимок мелкий, чёткость отличается больше чем в 1.6 раза или сняты разные области — тогда переснять, а не `--force`.
   **Самопроверка перед отправкой:** открой `…-compare.png` (Read) и убедись: обычный текст на обеих половинах читается без увеличения, показана одна и та же область, различие видно и обведено. Не читается → переснять. Нечитаемую склейку в тикет не прикладывать никогда.
5. **Список различий цифрами** — что и где: значение в Figma (`get_design_context`) против значения на сайте (`getComputedStyle` / `getBoundingClientRect`), например «כותרת: בעיצוב 24px bold, באתר 18px regular».
6. Figma недоступна (нет MCP или доступа к файлу) и макета в тикете нет → скажи пользователю и попроси снимок кадра; тикет только с фото сайта по расхождению с дизайном не создавай без его «да».
