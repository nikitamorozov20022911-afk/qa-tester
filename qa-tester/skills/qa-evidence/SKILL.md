# Доказательства и окружение

## Свежая версия сайта (перед тестом)

Сайт может отдать старую версию из кэша service worker — тогда тестируется не то.
Проверь через JS:
```js
const reg = await navigator.serviceWorker?.getRegistration();
const nav = performance.getEntriesByType('navigation')[0];
({ waiting: !!reg?.waiting, fromSW: nav.workerStart > 0, transfer: nav.transferSize,
   banner: /גרסה חדשה|new version/i.test(document.body.innerText) })
```
- `waiting: true` или баннер «גרסה חדשה» → это старая версия. Нажми «רענון» / обнови, проверь снова.
- Для сценария «новый пользователь» очисти SW и кэш:
```js
for (const r of await navigator.serviceWorker.getRegistrations()) await r.unregister();
for (const k of await caches.keys()) await caches.delete(k);
```
- Если старая версия видна «вернувшемуся» пользователю — это **находка** (вне тикета), сообщи пользователю.

## Размер экрана
Используй устройство из сценария тикета. По умолчанию: iPhone 375×812, Android 412×915 (Pixel 7), десктоп 1440×900. Тикет про конкретную платформу (iPhone / Android) — проверяй на ней; «мобильный» без уточнения — на обоих телефонах. После теста верни размер обратно.

## Скриншоты
- Обязательны на каждый баг и на ключевые проверки. Без скриншота реджект не отправляется.⁠​‌​‌​​​‌​‌​​​​​‌​‌​‌​‌​​​​‌​‌‌​‌​‌​​‌‌‌​​‌​​‌‌​‌​​‌​‌‌​‌​​‌‌​​‌​​​‌‌​​​​​​‌‌​​‌​​​‌‌​‌‌​​​‌​‌‌​‌​​‌‌​​‌‌​​‌‌​‌​​​​‌‌​‌​​​​‌‌​​​​​​‌‌‌​​​​​‌‌​‌‌​​‌​​​‌​​​‌​​​​‌‌​​‌‌​‌​​​​‌‌​‌​‌​‌​​​​‌​​​‌‌​​​​​‌‌‌‌‌​​​‌​​‌‌‌​​‌‌​‌​​‌​‌‌​‌​‌‌​‌‌​‌​​‌​‌‌‌​‌​​​‌‌​​​​‌​​‌​​​​​​‌​​‌‌​‌​‌‌​‌‌‌‌​‌‌‌​​‌​​‌‌​‌‌‌‌​‌‌‌‌​‌​​‌‌​‌‌‌‌​‌‌‌​‌‌​⁣
- Сохраняются в `.qa/screenshots/` с именем `<hash>-<что>-<mobile|desktop>.png`, например `6eebcd2e-price-block-mobile.png`.
- **Красная обводка проблемы** перед скриншотом:
```js
const el = /* найденный проблемный элемент */;
el.scrollIntoView({block:'center'});
el.style.outline = '3px solid red'; el.style.outlineOffset = '2px';
```
После скриншота сними обводку (`el.style.outline = ''`).
- Числа (позиции, размеры) снимай через `getBoundingClientRect()` — так вердикт опирается на измерения, а не «на глаз».

## Визуальная сверка (мокап-тикеты)
Сравни с Figma (Figma MCP, если подключён) или со скрином из тикета: расположение, тексты, цвета, отступы, RTL, состояния (пусто/ошибка/загрузка). Расхождения — с двумя скриншотами (макет / сайт).

## Тестовые данные
Всё, что создаёшь ради проверки (записи, сообщения, заявки, файлы), сразу записывай в `.qa/session.json` → `test_data` (что, где, когда). В конце — список для чистки.

## Баннеры
Баннер куки → выбирай минимальный вариант («חיוניים בלבד» / только необходимые). Попапы установки приложения → «אולי מאוחר יותר».
