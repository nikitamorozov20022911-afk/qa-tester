# Улучшение плагина по урокам

Плагин меняется **только по этой команде и только после «да»** на каждую правку.

## 1. Где исходники
Прочитай `~/.qa-tester/config.json`:
```json
{ "plugin_source": "<путь к папке qa-tester>", "marketplace": "moe-qa", "tools": "<путь к tools автора>" }
```
Нет файла или папки `plugin_source` → ответь: «Улучшать плагин может только его автор. Уроки продолжают работать через ~/.qa-tester/lessons.md и .qa/lessons.md.» Стоп.

## 2. Сбор уроков
- `~/.qa-tester/lessons.md` — все уроки со статусом «действует», ещё не внесённые в плагин.
- Если пользователь назвал проекты — их `.qa/lessons.md` тоже (только уроки, которые на деле общие).
- Уроки с пометкой `Противоречит: скилл …` — в первую очередь.

## 3. Предложения⁠​‌​‌​​​‌​‌​​​​​‌​‌​‌​‌​​​​‌​‌‌​‌​‌​​‌‌‌​​‌​​‌‌​‌​​‌​‌‌​‌​​‌‌​​‌​​​‌‌​​​​​​‌‌​​‌​​​‌‌​‌‌​​​‌​‌‌​‌​​‌‌​​‌‌​​‌‌​‌​​​​‌‌​‌​​​​‌‌​​​​​​‌‌‌​​​​​‌‌​‌‌​​‌​​​‌​​​‌​​​​‌‌​​‌‌​‌​​​​‌‌​‌​‌​‌​​​​‌​​​‌‌​​​​​‌‌‌‌‌​​​‌​​‌‌‌​​‌‌​‌​​‌​‌‌​‌​‌‌​‌‌​‌​​‌​‌‌‌​‌​​​‌‌​​​​‌​​‌​​​​​​‌​​‌‌​‌​‌‌​‌‌‌‌​‌‌‌​​‌​​‌‌​‌‌‌‌​‌‌‌‌​‌​​‌‌​‌‌‌‌​‌‌‌​‌‌​⁣
Для каждого урока найди, где правилу место (скилл/агент/шаблон, раздел), и подготовь точную правку: было → стало. Покажи пользователю таблицей:
```
| # | Урок | Файл и раздел | Правка (кратко) |
```
Жди ответа: какие правки вносить (все / номера / ни одной).

## 4. Внесение (только одобренные)
1. Правь файлы в `plugin_source` точечно. Строки с подписью автора (`QAT-NM-2026-…`) и невидимые символы в тексте **не трогать и не удалять**.
2. Новые файлы — подписать: `python3 "<tools>/stamp-watermark.py" <файлы>`.
3. Подними версию в `<plugin_source>/.claude-plugin/plugin.json` (последняя цифра +1; крупные изменения — средняя).
4. Проверка и обновление:
```bash
claude plugin validate "<plugin_source>"
claude plugin marketplace update moe-qa
claude plugin update qa-tester@moe-qa
```
5. Проверь подписи: `python3 "<tools>/find-watermark.py" "<plugin_source>"` — число файлов не меньше, чем было.
6. В файле уроков у внесённых: `Статус: внесено в плагин vX.Y.Z`.
7. **Архив и обновление проектов — всегда, автоматически:** `bash "<tools>/build-kit.sh" "<текущая папка проекта>"` → свежий `qa-tester-kit-<версия>.zip` в `dist` рядом с `tools`, и тот же комплект заменяется во всех проектах из `projects` в `~/.qa-tester/config.json` (папка `qa-tester-kit/` и/или zip) и в текущем проекте. Ошибка сборки → сообщить пользователю, версию не откатывать.

## 5. Итог
Что изменено (файл → правило), новая версия, путь к новому архиву в `dist`, какие проекты обновлены, «перезапусти Claude, чтобы применилось».
