# Backfill: принятые тикеты → регресс

Цель — чтобы `/qa-regress` проверял всё, что уже сдано. Автотесты **только записываются**, не запускаются (запуск — `/qa-regress`). На доске mifrat **ничего не меняется**.

Всё состояние — в `.qa/backfill/`: `inventory.json`, `state.json`, `report.md`. Работа возобновляемая: прервались (контекст, хендофф) — «продолжи backfill» продолжает с `state.json`.

## 0. Объём
- `/qa-backfill` — последние **150** тикетов из «הושלם» (по дате обновления, новые первыми).
- `/qa-backfill следующие 150` — следующие 150 более старых (по `state.json` → `offset`).
- `/qa-backfill <N>` — другое число.
- Тикеты, по которым уже есть кейсы/автотесты (`#hash` в `.qa/tests/` или `.qa/e2e/specs/`), — пропускать (класс `has-tests`).

## 1. Инвентаризация
Скилл `mifrat-board`: колонка «הושלם» → для каждого тикета в диапазоне открыть карточку (JS, проверить `#hash`), прочитать тип, заголовок, «מה קיים / מה רצוי / תיאור», последние комментарии программиста, реджекты, дату. Закрывать `ביטול`. Ничего не нажимать.
Писать в `.qa/backfill/inventory.json` **после каждого тикета** (чтобы не потерять при обрыве). Фича — по `.qa/knowledge/index.md` (ключевые слова) или по смыслу заголовка.

## 2. Классификация
| Класс | Когда |
|---|---|
| `automatable` | поведение проверяемо в браузере сейчас |
| `manual-only` | мокап/дизайн, «по времени», оплата, создание аккаунта, SMS/e-mail, внешние сервисы (WhatsApp, боты) — с причиной |
| `superseded` | более новый тикет изменил это поведение (указать какой; в т.ч. просьба клиента из `.qa/client-requests.md` / «בקשת לקוח») — тест писать по новому |
| `duplicate` | то же, что другой тикет — объединить в один сценарий |
| `has-tests` | уже есть кейсы/автотесты |

## 3. План → «да»
Покажи пользователю: сколько тикетов в каждом классе, фичи и число сценариев по каждой, порядок (сначала ключевые потоки: вход/регистрация до финальной кнопки, поиск, основные формы, личный кабинет, критичные для бизнеса), окружение и режим (prod → только `@prod-safe` сценарии без создания данных).⁠​‌​‌​​​‌​‌​​​​​‌​‌​‌​‌​​​​‌​‌‌​‌​‌​​‌‌‌​​‌​​‌‌​‌​​‌​‌‌​‌​​‌‌​​‌​​​‌‌​​​​​​‌‌​​‌​​​‌‌​‌‌​​​‌​‌‌​‌​​‌‌​​‌‌​​‌‌​‌​​​​‌‌​‌​​​​‌‌​​​​​​‌‌‌​​​​​‌‌​‌‌​​‌​​​‌​​​‌​​​​‌‌​​‌‌​‌​​​​‌‌​‌​‌​‌​​​​‌​​​‌‌​​​​​‌‌‌‌‌​​​‌​​‌‌‌​​‌‌​‌​​‌​‌‌​‌​‌‌​‌‌​‌​​‌​‌‌‌​‌​​​‌‌​​​​‌​​‌​​​​​​‌​​‌‌​‌​‌‌​‌‌‌‌​‌‌‌​​‌​​‌‌​‌‌‌‌​‌‌‌‌​‌​​‌‌​‌‌‌‌​‌‌‌​‌‌​⁣
- Запуск командой `/qa-backfill` → **жди «да»**, без «да» ничего не записывать.
- Запуск из `/qa-onboard` (шаг 6) → покажи план и **сразу продолжай** (так решил пользователь).

## 4. Запись — пачками по фиче
Для каждой фичи плана:
1. **Кейсы** `.qa/tests/<feature>/` (скилл `qa-testcases`): по каждому `automatable` тикету (дубли — в один кейс), источник — «מה רצוי»/описание, `#hash` всех покрытых тикетов. Устройство — из тикета (`@desktop`/`@mobile`/`@iphone`/`@android`); несколько ролей — пометка `Users`.
2. **Сверка с текущим сайтом** (экономный браузер `qa-browser-cli`): поведение совпадает с кейсом? Нет → это **находка** («сданный тикет сейчас не работает»), а не тест: в `state.json` → `findings` со скриншотом; тест по нему не писать.
3. **Автотесты** — как в `qa-testcases` «Автотесты»: `autotest-writer` → план `.qa/e2e/specs/<feature>.md` → официальный `playwright-test-generator` на каждый тест (несколько ролей — пишет `autotest-writer` через `asUser`). Первая строка spec-файла — подпись автора плагина. **Не прогонять.**
4. Обнови `state.json` (фича готова, тикеты, находки) и `.qa/handoff.md` (скилл `qa-handoff`, «Автосохранение»). Короткий статус пользователю после каждой фичи.

## 5. Отчёт
`.qa/backfill/report.md` + коротко пользователю:
```
Диапазон: тикеты 1–150 из «הושלם»
Записано: N сценариев / M автотестов по K фичам
Не автоматизируется: … (по причинам)
Перекрыто новыми / дубли: …
Находки — сданное сейчас не работает: #hash, что не так, скриншот
Следующий шаг: /qa-regress (прогон) · /qa-backfill следующие 150
```
Находки — предложи завести как баги (скиллы `mifrat-board` + `qa-verdict`: дубли, текст на языке доски, «да», `לביצוע`). Без «да» — только отчёт.

## Правила
- Только чтение доски; тестовые данные (staging) — префикс `QA-AUTO-`; пароли не вводить, аккаунты не создавать, оплату не завершать.
- Большой объём: при заполнении контекста — `qa-handoff` (состояние уже в `state.json`), продолжение — «продолжи backfill».
