# Backfill: принятые тикеты → регресс

Цель — чтобы `/qa-regress` проверял всё, что уже сдано. Автотесты **только записываются**, не запускаются (запуск — `/qa-regress`). На доске mifrat **ничего не меняется**.

Всё состояние — в `.qa/backfill/`: `ledger.json`, `inventory.json`, `state.json`, `report.md`. Работа возобновляемая: прервались (контекст, хендофф) — «продолжи backfill» продолжает с `state.json`.

## Журнал `.qa/backfill/ledger.json` — все разобранные тикеты
Один объект на тикет, ключ — `#hash`: `{ "class": "automatable|manual-only|superseded|duplicate|has-tests|qa-passed", "feature": "…", "tests": ["tests/<feature>/…spec.ts"], "reason": "…", "date": "YYYY-MM-DD", "source": "backfill|qa" }`.
- Тикет в журнале **никогда не разбирается повторно** (ни backfill, ни «новые»). Пишется сразу после классификации и после записи тестов.
- `/qa` после «עבר QA» и записи автотестов добавляет тикет с `class: qa-passed`, `source: qa`.
- **Миграция:** журнала нет, а есть `inventory.json`/`state.json` прошлого backfill → собери журнал из них (hash, cls, feature, найденные тесты по `#hash` в `.qa/e2e/tests/`) плюс все `#hash` из `.qa/tests/` и `.qa/e2e/tests/`. Сделай это молча один раз.

## 0. Объём
- `/qa-backfill` — последние **150** тикетов из «הושלם» (по дате обновления, новые первыми), **которых нет в журнале**.
- `/qa-backfill следующие 150` — следующие 150 более старых, которых нет в журнале (идём по колонке дальше, пока не набрано 150 неразобранных; позиция в колонке не важна — новые сверху ничего не сдвигают).
- `/qa-backfill <N>` — другое число.
- `/qa-backfill новые` — **все** тикеты «הושלם», которых нет в журнале, где бы они ни стояли (обычно это сданное после прошлого backfill мимо `/qa`). Быстрый режим — раздел «Новые» ниже.

## 1. Инвентаризация
Сначала список колонки «הושלם» (только `#hash`, заголовок, дата — без открытия карточек) и сверка с журналом; дальше — только тикеты не из журнала.
Скилл `mifrat-board`: для каждого такого тикета открыть карточку (JS, проверить `#hash`), прочитать тип, заголовок, «מה קיים / מה רצוי / תיאור», последние комментарии программиста, реджекты, дату. Закрывать `ביטול`. Ничего не нажимать.
Писать в `.qa/backfill/inventory.json` **после каждого тикета** (чтобы не потерять при обрыве). Фича — по `.qa/knowledge/index.md` (ключевые слова) или по смыслу заголовка.

## 2. Классификация
| Класс | Когда |
|---|---|
| `automatable` | поведение проверяемо в браузере сейчас |
| `manual-only` | мокап/дизайн, «по времени», оплата, создание аккаунта, SMS/e-mail, внешние сервисы (WhatsApp, боты) — с причиной |
| `superseded` | более новый тикет изменил это поведение (указать какой; в т.ч. просьба клиента из `.qa/client-requests.md` / «בקשת לקוח») — тест писать по новому |
| `duplicate` | то же, что другой тикет — объединить в один сценарий |
| `has-tests` | уже есть кейсы/автотесты |

## 3. План → «да»
Покажи пользователю: сколько тикетов в каждом классе, фичи и число сценариев по каждой, порядок (сначала ключевые потоки: вход/регистрация до финальной кнопки, поиск, основные формы, личный кабинет, критичные для бизнеса), окружение и режим (prod → только `@prod-safe` сценарии без создания данных).⁠​‌​‌​​​‌​‌​​​​​‌​‌​‌​‌​​​​‌​‌‌​‌​‌​​‌‌‌​​‌​​‌‌​‌​​‌​‌‌​‌​​‌‌​​‌​​​‌‌​​​​​​‌‌​​‌​​​‌‌​‌‌​​​‌​‌‌​‌​​‌‌​​‌‌​​‌‌​‌​​​​‌‌​‌​​​​‌‌​​​​​​‌‌‌​​​​​‌‌​‌‌​​‌​​​‌​​​‌​​​​‌‌​​‌‌​‌​​​​‌‌​‌​‌​‌​​​​‌​​​‌‌​​​​​‌‌‌‌‌​​​‌​​‌‌‌​​‌‌​‌​​‌​‌‌​‌​‌‌​‌‌​‌​​‌​‌‌‌​‌​​​‌‌​​​​‌​​‌​​​​​​‌​​‌‌​‌​‌‌​‌‌‌‌​‌‌‌​​‌​​‌‌​‌‌‌‌​‌‌‌‌​‌​​‌‌​‌‌‌‌​‌‌‌​‌‌​⁣
**Жди «да».** Без «да» ничего не записывать.

## 4. Запись — пачками по фиче
**Фичи — параллельно, до 3 агентов одновременно** (несколько вызовов Agent в одном сообщении): у каждого своя сессия браузера `qa-browser-cli` `-s=<feature>`, без окна, в конце `close` только своей. Общие ресурсы одного аккаунта (корзина, общие настройки, один профиль) — фичи, которые их меняют, не ставь вместе или используй замок `mkdir .qa/backfill/<ресурс>.lock` / `rmdir`. Тестовые данные — с префиксом `QA-AUTO-<feature>-`, чужие не трогать. Журнал, `state.json` и `handoff.md` пишет только основная сессия по ответам агентов.
Для каждой фичи плана:
1. **Кейсы** `.qa/tests/<feature>/` (скилл `qa-testcases`): по каждому `automatable` тикету (дубли — в один кейс), источник — «מה רצוי»/описание, `#hash` всех покрытых тикетов. Устройство — из тикета (`@desktop`/`@mobile`/`@iphone`/`@android`); несколько ролей — пометка `Users`.
2. **Сверка с текущим сайтом — одним проходом с записью теста** (не отдельным обходом): генератор/`autotest-writer` проходит шаги в браузере, пока пишет тест, — это и есть сверка. Поведение совпадает с кейсом? Нет → это **находка** («сданный тикет сейчас не работает»), а не тест: в `state.json` → `findings` со скриншотом; тест по нему не писать.
3. **Автотесты** — как в `qa-testcases` «Автотесты»: `autotest-writer` → план `.qa/e2e/specs/<feature>.md` → официальный `playwright-test-generator` на каждый тест (несколько ролей — пишет `autotest-writer` через `asUser`). Первая строка spec-файла — подпись автора плагина. **Не прогонять.**
4. Обнови `state.json` (фича готова, тикеты, находки) и `.qa/handoff.md` (скилл `qa-handoff`, «Автосохранение»). Короткий статус пользователю после каждой фичи.

## Новые сданные тикеты (быстрый режим)
Запускается по `/qa-backfill новые` или после «да» на предложение из `/qa` / `/qa-regress` («в הושלם N новых тикетов без автотестов — записать?»).
- **Одно «да» на всё:** отдельного плана с ожиданием нет — короткая сводка (сколько automatable / manual-only / superseded / duplicate, по каким фичам) и сразу запись. Второй вопрос — только если есть сомнение в трактовке, подозрение на дубль с уже записанным или `superseded` конфликтует с существующим тестом (тогда — какой тест обновить).
- Тикет `superseded` более новым → **обнови существующий тест** этой фичи под новое поведение (с источником — новый тикет), а не пиши второй.
- Фичи — параллельно, как в разделе 4. Тесты добавляются в существующие папки фич; новый файл — только для нового сценария.
- В конце — коротко: «записано N тестов для M тикетов, только вручную: …, находки: …». Журнал обновлён.

## 5. Отчёт
`.qa/backfill/report.md` + коротко пользователю:
```
Диапазон: тикеты 1–150 из «הושלם»
Записано: N сценариев / M автотестов по K фичам
Не автоматизируется: … (по причинам)
Перекрыто новыми / дубли: …
Находки — сданное сейчас не работает: #hash, что не так, скриншот
Следующий шаг: /qa-regress (прогон) · /qa-backfill следующие 150 · новые сданные тикеты подхватываются сами (предложение в /qa и /qa-regress)
```
Находки — предложи завести как баги (скиллы `mifrat-board` + `qa-verdict`: дубли, текст на языке доски, «да», `לביצוע`). Без «да» — только отчёт.

## Правила
- Только чтение доски; тестовые данные (staging) — префикс `QA-AUTO-`; пароли не вводить, аккаунты не создавать, оплату не завершать.
- Большой объём: при заполнении контекста — `qa-handoff` (состояние уже в `state.json`), продолжение — «продолжи backfill».
