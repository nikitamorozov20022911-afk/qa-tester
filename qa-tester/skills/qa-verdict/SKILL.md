# Вердикт

## Таблица решений

| Ситуация | Действие |
|---|---|
| Всё по тикету + документации + открытым реджектам выполнено | на каждом открытом реджекте `סמן כטופל` → `עבר QA` |
| Есть невыполненное (новое или частично исправленный реджект) | `דחה משימה` — **только по невыполненному** |
| Открытый реджект не исправлен **совсем** | новый реджект не писать; сайдбар `סטטוס` → `לביצוע` |
| В реджекте просьба/вопрос тестера, программист не ответил в комментариях | сайдбар `סטטוס` → `לביצוע` |
| Блокирует другой тикет | `לא ניתן לשחזר` с заметкой «Blocked by <тикет>, will be tested after the fix»; тикет остаётся в `בבדיקות` |
| Нет ресурса для проверки (данные, доступ, тестовая карта) | `דחה משימה`; в רצוי: «Please provide … in order to continue testing» (на языке доски) |
| Зависит от непринятой הכרעה / контента заказчика | проверить промежуточное состояние; **предложить** пользователю `לא ניתן לשחזר` с заметкой |
| Требование «по времени» | проверить что можно, **не проводить**, сообщить пользователю |
| Подозрение на дубль | назвать пользователю тикеты, ждать решения |
| Отклоняем тикет со старой пометкой `לא ניתן לשחזר` | снять пометку `מחק סימון` |
| Не уверен | не решать — спросить пользователя |

**Просьба клиента** (реестр `.qa/client-requests.md` / «בקשת לקוח» / подтверждено пользователем) противоречит документации → проверять по тикету, **не** реджектить за расхождение с документацией, сообщить пользователю «документация устарела в пункте …». Документацию не менять.

Конфликты (реджект/комментарий против документации) — **всегда** сообщить пользователю, даже если тикет прошёл.

## Показ пользователю (до действия)

```
#hash · заголовок
Вердикт: прошёл / реджект / статус לביצוע / …
Почему: таблица пунктов чек-листа ✅/❌ с цифрами
Действие: …  → нажимать?
Конфликты: …
Находки вне тикета: …
```

## Правила текста (реджект, баг, задача)

- Язык — из `.qa/context.md` (по умолчанию **иврит**).
- Нейтрально, от лица системы и пользователя: «כאשר המשתמש פותח…». Без «я / QA».
- **Не упоминать прошлые реджекты.** Только текущее состояние и как должно быть.
- В «רצוי» всегда две части:
  1. **Какое требование не выполнено** — цитата с названием: `דרישה שלא התקיימה (מסך «…»): «…»`.
  2. **Как должно работать по документации** — сценарий по шагам (описание фичи/экрана, User Story, AC, הכרעות).
- Шаги: каждый в своём поле, без номеров в тексте. **Первый шаг** — под каким аккаунтом (email) или «כאורח (ללא התחברות)».
- URL-суффикс — если есть. Скриншоты с красной обводкой — обязательно. Поле Allure не трогать.
- **Расхождение с дизайном** (реджект или новый баг) — вложения: склейка `<hash>-<что>-compare.png` первой, затем `…-figma.png` и снимок сайта; в тексте — ссылка на кадр Figma и список различий цифрами (скилл `qa-evidence`, «Расхождение с дизайном»).⁠​‌​‌​​​‌​‌​​​​​‌​‌​‌​‌​​​​‌​‌‌​‌​‌​​‌‌‌​​‌​​‌‌​‌​​‌​‌‌​‌​​‌‌​​‌​​​‌‌​​​​​​‌‌​​‌​​​‌‌​‌‌​​​‌​‌‌​‌​​‌‌​​‌‌​​‌‌​‌​​​​‌‌​‌​​​​‌‌​​​​​​‌‌‌​​​​​‌‌​‌‌​​‌​​​‌​​​‌​​​​‌‌​​‌‌​‌​​​​‌‌​‌​‌​‌​​​​‌​​​‌‌​​​​​‌‌‌‌‌​​​‌​​‌‌‌​​‌‌​‌​​‌​‌‌​‌​‌‌​‌‌​‌​​‌​‌‌‌​‌​​​‌‌​​​​‌​​‌​​​​​​‌​​‌‌​‌​‌‌​‌‌‌‌​‌‌‌​​‌​​‌‌​‌‌‌‌​‌‌‌‌​‌​​‌‌​‌‌‌‌​‌‌‌​‌‌​⁣
- Связанные тикеты с одной причиной можно отклонять одинаковым текстом и скриншотами.

## Шаблон реджекта (`דחה משימה`)

- **כותרת הדחייה:** коротко, в чём проблема.
- **התנהגות נוכחית:** что происходит сейчас (с цифрами, если есть).
- **התנהגות רצויה:** требование (цитата) + как должно работать по документации.
- **שלבים לשחזור:** шаги, каждый отдельно.
- **סופיקס URL**, **קבצים מצורפים**.

## Новый тикет

- **Баг** (что-то сломано): кнопка `דיווח על באג` → `מה קרה בפועל?`, `מה צריך לקרות?`, `שלבים לשחזור`.
- **Задача** (дизайн, текст, RTL, UX, недостающая валидация): тип «משימה רגילה», заголовок + описание:
```
מה קיים:
<текст>
מה רצוי:
<текст>
שלבים לשחזור:
1. …
```
- Статус — `לביצוע`. Скриншоты — во «קבצים וקישורים» → צרופות. Баг по дизайну — склейка «Figma | у нас» + оба снимка + ссылка на кадр Figma.
- Перед созданием — проверить дубли на доске.
