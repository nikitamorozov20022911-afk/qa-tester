# Вердикт

## Ворота перед вердиктом (обязательно)

Вердикт выносится **только когда все пять пунктов закрыты**. Хоть один открыт → не вердикт, а «не готово: <чего не хватает>» и что нужно, чтобы закрыть.
1. **Тикет:** каждое требование «מה קיים / מה רצוי» и шагов — в карте требований (`qa-ticket-analysis`, раздел 4) и проверено.
2. **Документация:** найдена фича/экран тикета и сверены относящиеся AC — или прямо записано «в документации требований к этому нет» (после поиска, не по догадке).
3. **Figma:** тикет про дизайн → сверен с кадром (ссылка `node-id`); не про дизайн → записано почему.
4. **Связанные тикеты:** проверены, у каждого класс (`qa-ticket-analysis`, 2b); «блокирует» / «противоречит» / «дубль» учтены в вердикте.
5. **Каждый пункт карты** имеет результат ✅ / ❌ с фактами. «⚠️ не проверить» допустим только с причиной — и тогда вердикт «прошёл» невозможен, только вопрос пользователю.

Вердикт опирается только на пункты карты. Требование, которого нет ни в тикете, ни в документации, ни в Figma, — не причина реджекта (это «находка»).

## Таблица решений

| Ситуация | Действие |
|---|---|
| Всё по тикету + документации + открытым реджектам выполнено | на каждом открытом реджекте `סמן כטופל` → сказать пользователю нажать `עבר QA` (сам агент не нажимает) |
| Есть невыполненное (новое или частично исправленный реджект) | `דחה משימה` — **только по невыполненному** |
| Открытый реджект не исправлен **совсем** | новый реджект не писать; сайдбар `סטטוס` → `לביצוע` |
| В реджекте просьба/вопрос тестера, программист не ответил в комментариях | сайдбар `סטטוס` → `לביצוע` |
| Блокирует другой тикет | `לא ניתן לשחזר` с заметкой «Blocked by <тикет>, will be tested after the fix»; тикет остаётся в `בבדיקות` |
| Нет ресурса для проверки (данные, доступ, тестовая карта) | `דחה משימה`; в רצוי: «Please provide … in order to continue testing» (на языке доски) |
| Зависит от непринятой הכרעה / контента заказчика | проверить промежуточное состояние; **предложить** пользователю `לא ניתן לשחזר` с заметкой |
| Требование «по времени» | проверить что можно, **не проводить**, сообщить пользователю |
| Подозрение на дубль | назвать пользователю тикеты, ждать решения |
| Отклоняем тикет со старой пометкой `לא ניתן לשחזר` | снять пометку `מחק סימון` |
| Не уверен | не решать — спросить пользователя |

**Просьба клиента** (реестр `.qa/client-requests.md` / «בקשת לקוח» / подтверждено пользователем) противоречит документации → проверять по тикету, **не** реджектить за расхождение с документацией, сообщить пользователю «документация устарела в пункте …». Документацию не менять.

Конфликты (реджект/комментарий против документации) — **всегда** сообщить пользователю, даже если тикет прошёл.

## Показ пользователю (до действия)

Вердикт показывается так, чтобы пользователь мог ответить **«делай как сказал»** и быть уверен, что ничего не пропущено: всё проверенное видно, всё, что будет сделано, перечислено точно.

```
#hash · заголовок
Вердикт: прошёл / реджект / статус לביצוע / …

Проверено по:
  тикет — מה קיים / מה רצוי / шаги
  документация — <фича/экран, раздел> (или «требований к этому нет»)
  Figma — <ссылка node-id> (или «не относится: …»)
  связанные — <#a вместе, #b уже сделан> (или «нет»)

| № | Требование | Источник | Результат | Факты (цифры, тексты) | Скриншот |
(все пункты карты, без пропусков; ❌ — перепроверены bug-verifier)

Не проверено: нет  (или список с причиной — тогда вердикт не «прошёл»)

Сделаю (по порядку):
  1. <действие на доске, например «סמן כטופל на реджекте "…"»>
  2. <«דחה משימה» — пункты Д2, F1; текст ниже>
  …
Текст реджекта/бага: <полный, как уйдёт на доску>
Конфликты: …
Находки вне тикета (в вердикт не входят): …
```

**«Делай как сказал» / «да»** = выполнить ровно список «Сделаю», в этом порядке и с этим текстом. Ничего не добавлять, не менять текст, не пропускать. Если при выполнении что-то не совпало с показанным (`#hash` другой, реджект уже закрыт, кнопки нет) → остановиться и сказать, не импровизировать.

## Правила текста (реджект, баг, задача)

- Язык — из `.qa/context.md` (по умолчанию **иврит**).
- Нейтрально, от лица системы и пользователя: «כאשר המשתמש פותח…». Без «я / QA».
- **Не упоминать прошлые реджекты.** Только текущее состояние и как должно быть.
- В «רצוי» всегда две части:
  1. **Какое требование не выполнено** — цитата с названием: `דרישה שלא התקיימה (מסך «…»): «…»`.
  2. **Как должно работать по документации** — сценарий по шагам (описание фичи/экрана, User Story, AC, הכרעות).
- Шаги: каждый в своём поле, без номеров в тексте. **Первый шаг** — под каким аккаунтом (email) или «כאורח (ללא התחברות)».
- URL-суффикс — если есть. Скриншоты с красной обводкой — обязательно. Поле Allure не трогать.
- **Расхождение с дизайном** (реджект или новый баг) — вложение **одно**: склейка `<hash>-<что>-compare.png` («как в Figma» + «как у нас» в одной картинке, места отличий обведены красным на обеих половинах). Отдельные `…-figma.png` и снимок сайта не прикладывать — только если программист попросит или склейка слишком длинная (тогда несколько склеек по блокам, а не россыпь фото); в тексте — ссылка на кадр Figma и список различий цифрами (скилл `qa-evidence`, «Расхождение с дизайном»). Перед отправкой открой склейку и проверь, что текст на обеих половинах читается и область одна и та же; мелкая/размытая склейка = реджект не отправлять, переснять.⁠​‌​‌​​​‌​‌​​​​​‌​‌​‌​‌​​​​‌​‌‌​‌​‌​​‌‌‌​​‌​​‌‌​‌​​‌​‌‌​‌​​‌‌​​‌​​​‌‌​​​​​​‌‌​​‌​​​‌‌​‌‌​​​‌​‌‌​‌​​‌‌​​‌‌​​‌‌​‌​​​​‌‌​‌​​​​‌‌​​​​​​‌‌‌​​​​​‌‌​‌‌​​‌​​​‌​​​‌​​​​‌‌​​‌‌​‌​​​​‌‌​‌​‌​‌​​​​‌​​​‌‌​​​​​‌‌‌‌‌​​​‌​​‌‌‌​​‌‌​‌​​‌​‌‌​‌​‌‌​‌‌​‌​​‌​‌‌‌​‌​​​‌‌​​​​‌​​‌​​​​​​‌​​‌‌​‌​‌‌​‌‌‌‌​‌‌‌​​‌​​‌‌​‌‌‌‌​‌‌‌‌​‌​​‌‌​‌‌‌‌​‌‌‌​‌‌​⁣
- Связанные тикеты с одной причиной можно отклонять одинаковым текстом и скриншотами.

## Шаблон реджекта (`דחה משימה`)

- **כותרת הדחייה:** коротко, в чём проблема.
- **התנהגות נוכחית:** что происходит сейчас (с цифрами, если есть).
- **התנהגות רצויה:** требование (цитата) + как должно работать по документации.
- **שלבים לשחזור:** шаги, каждый отдельно.
- **סופיקס URL**, **קבצים מצורפים**.

## Новый тикет

- **Баг** (что-то сломано): кнопка `דיווח על באג` → `מה קרה בפועל?`, `מה צריך לקרות?`, `שלבים לשחזור`.
- **Задача** (дизайн, текст, RTL, UX, недостающая валидация): тип «משימה רגילה», заголовок + описание:
```
מה קיים:
<текст>
מה רצוי:
<текст>
שלבים לשחזור:
1. …
```
- **Подробность — как у реджекта** (все «Правила текста» выше). Баг/задача из аудита (`/qa-negative`, `/qa-ux`, `/qa-full`, мобильные) — тем же уровнем, не короче:
  - **Заголовок:** экран + что не так + как должно быть (не 3–4 слова).
  - **מה קיים:** где (экран, роль), какое действие привело, что именно видно — точные тексты в кавычках, цифры; почему это проблема для пользователя (с чем путается, что теряет, что может сделать лишнего). 2–4 предложения.
  - **מה רצוי:** обе части — `דרישה שלא התקיימה (מסך «…»): «…»` из `.qa/knowledge/` / документации + как должно работать по шагам. Требования в документации нет → прямо написать «בתיעוד אין דרישה מפורשת» и опору: как это сделано в других местах системы (экран, текст) или общее правило (валидация, единые термины). Не одна фраза «change X to Y».
  - **שלבים לשחזור:** первый — аккаунт (email/роль) или «כאורח», дальше каждое действие отдельно, последний — что увидеть.
  - Язык — только из `.qa/context.md` (не английский по умолчанию).

  **Плохо (так не писать):** מה קיים: `In "המשרות שלי" -> "העברה לארכיון" on a job, the dialog has the button "לסגור את המכרז".` / מה רצוי: `change the name from "לסגור את המכרז" to "לסגור את המשרה"`.

  **Хорошо:**
  ```
  כותרת: דיאלוג «העברת משרה» — כפתור האישור נקרא «לסגור את המכרז» במקום «לסגור את המשרה»
  מה קיים:
  כאשר הד-האנטר לוחץ «העברה לארכיון» על משרה במסך «המשרות שלי», נפתח הדיאלוג «העברת משרה». כפתור האישור בדיאלוג נקרא «לסגור את המכרז». «מכרז» הוא ישות אחרת במערכת, ולכן המשתמש עלול לחשוב שהפעולה סוגרת מכרז ולא את המשרה שבחר.
  מה רצוי:
  דרישה שלא התקיימה (מסך «המשרות שלי»): «…ציטוט מהתיעוד…»
  כיצד צריך לעבוד: המשתמש לוחץ «העברה לארכיון» על משרה → נפתח הדיאלוג «העברת משרה» → כפתור האישור נקרא «לסגור את המשרה», וכל הטקסטים בדיאלוג מתייחסים למשרה → לאחר האישור המשרה עוברת לארכיון.
  שלבים לשחזור:
  התחברות כהד-האנטר (email)
  פתיחת המסך «המשרות שלי»
  לחיצה על «העברה לארכיון» באחת המשרות
  בדיאלוג «העברת משרה» — לבדוק את הטקסט של כפתור האישור
  ```
- Перед созданием — показать пользователю полный текст тикета (заголовок, מה קיים, מה רצוי, шаги, URL, скриншоты) и ждать «да».
- Статус — `לביצוע`. Скриншоты — во «קבצים וקישורים» → צרופות. Баг по дизайну — одна склейка «Figma | у нас» с красной обводкой + ссылка на кадр Figma.
- Перед созданием — проверить дубли на доске.
